# 交付报告 · 三步链路（架构 SSOT）

> 取代「厚流水线」作为 **v3** 产品可见模型。验收铁律 / P1–P6 / P4 规格锁 **不变**。  
> Flag：`DELIVERY_PIPELINE=v3_three_step`（见 `lib/llm/pro/delivery/pipeline-v3/flag.ts`）。

## 三步（Lab = 生产同尺）

| 步 | 名称 | 做什么 | 不做什么 |
|----|------|--------|----------|
| **① 内容生成** | 正文 + 原始依据批断 | 短提示词 + 本案真算/菜单；质量只来自喂料与提示词 | **不加质量闸**；不剥句；不质量抽奖重试 |
| **② 闸门验收** | 尺 | 对①**冻结稿**人审 + 机闸；只判过/不过 | **不改稿**；不过 → 改 prompt/菜单后重跑① |
| **③ 依据合规** | 翻译依据 | 大白话连接 + `⟦t:⟧` 自造术语 | 不改正文；不把 P3+ 写成批断译文 |

## Step① 内部（有依据页）

仍 **先批断、后正文** 两次独立 270s 分发（产品算一步「内容」）：

1. `content.judgment` — 原始批断（可含闭集真词；不打 `⟦t:⟧`）
2. `content.body` — 白话正文（零命理专名；P2=译批断；P3+=可执行扎根）

**P1 也两步**：`direct_answer.content.judgment`（path=core_judgment/primary/backup 真算根）→ `content.body`（主辅白话）。产品 UI **仍不挂**依据折层；批断只供生成与 Lab 人审。无 `evidence_soft`。

两枪之间与枪内：**无质量闸**（仅 JSON 可落库 / 运输级失败可新分发）。

## Step② Phase A → B

- **Phase A（当前）**：最小形状能进预览 + **人审 checklist**（验收标准文档）。
- **Phase B（后加）**：按故障**类别**加硬尺；禁止 soft-strip→thin。
- **退出账本**：人审失败类别与冻结门槛（连续 N 次通过 × M 种异盘）见 `交付v3-Lab人审失败类别-待冻结闸门清单.md`——达标必须冻结提示词并转闸，禁止无限拖。
- **生产运维（待建）**：Lab 测稳后建闸门失败收集台（完整诊断字段 + 薄聚合 UI），见 `交付v3-闸门运维收集台-待建.md`。

## Step③

仅 Step② 通过后解锁。输出展示用依据；正文不动。

## 因果链

任一步未达标 → 禁止推进下一步（含 Lab「本步通过」与生产解锁）。  
闸门不过 → 回改生成侧，禁止闸门内修稿装合格。

## 与旧链（硬边界）

- **禁止**在旧 `assign / write / fill / sanitize / p4-means-gate soft-strip` 上继续打补丁。
- v3 = **greenfield**：`lib/llm/pro/delivery/pipeline-v3/**` + 独立 Lab 步骤表 + 独立 `run-step-v3`。
- 旧链冻结只读；旧 Lab 步骤 ID 与 v3 **不兼容**；新 `lab_id` + `DELIVERY_PIPELINE=v3_three_step` 起跑。
- 可 **import 只读工具**（callLLM、Fact-pack 装订、术语表、UI 组件），不可复用旧质量闸/剥句路径。
