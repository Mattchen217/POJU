> Flag：`DELIVERY_PIPELINE=v3_three_step`（见 `lib/llm/pro/delivery/pipeline-v3/flag.ts`）。  
> **分步职责与合格尺（细步矩阵 · 翻车归属）**：`交付v3-分步职责与合格尺-SSOT.md` —— Lab 改 duty/闸前必读。

## 三步（Lab = 生产同尺）

| 步 | 名称 | 做什么 | 不做什么 |
|----|------|--------|----------|
| **① 内容生成** | 批断 + 正文 | 短提示词 + **本页白名单喂料**（`page-feed-policy.ts`）；质量只来自喂料与提示词 | **枪内**不加质量返工；不剥句；不质量抽奖重试；**不整包灌无关菜单/锁盘** |
| **② 闸门验收** | 尺 | 对①**冻结稿**人审 + 机闸；只判过/不过 | **验收层不改稿**；不过 → 改 prompt/菜单后重跑① |
| **②→③（P3 试点）** | 可见层润色 `body_polish` | 加厚读感 + 清表面专名/引号/X%；事实主张冻结 | 不改正文事实/门槛/条数；规格见 `交付v3-正文润色-body_polish-规格.md` |
| **③ 依据合规** | 翻译依据 | 大白话连接 + `⟦t:⟧` 自造术语 | 不改正文；不把 P3+ 写成批断译文 |

**页级喂料**：操作手册 §2.1。目的是页责匹配、防串页污染——不是「去掉某种真算」。奇门锁盘仅 P4 授权。

## 改输出的三条界（A / B / C · 硬）

旧口号「闸门只验不改」易误伤：**验收闸**与**确定性装配**不是一类事。

| 类 | 名称 | 规则 | 例 |
|----|------|------|----|
| **A** | 验收闸 | **只判过/不过**；不过 → 回改 duty/喂料/提示词后重跑① | `gate_p4_*`、人审 checklist |
| **B** | 确定性装配 | 代码能算对的槽位 **立刻盖回/钉死**；不必等「生成侧调好」 | `coercePlan` 钉 path / `means_candidate_ref` / `moat_class`；polish 后 `stampChartAnchorsFromDraft` |
| **C** | 质量伪修 | **任何阶段禁止**：剥句凑过闸、塞模板句、正则关键词当「covered」 | 旧 soft-strip、vernacular enrich 妆合格 |

**判据**：该值「模型判断 vs 代码真算」谁更可信？  
- 代码可确定性算对（闭集 ref、moat 轮转、派工 path、已有 cite 抽锚）→ **B，现在就接管**（也让 Lab 观察生成质量时少一层槽位噪音）。  
- 须综合判断（这段该不该写、怎么写才贴此人）→ **只靠 prompt/喂料；A 只验打回，永不代写内容**。  
- 无真算依据的装饰 → **C，永禁**。

> Step①「不加质量闸」= **生成枪内**不靠 A/C 装合格；落库前允许 **B 装配**；落库后 early 类别机检属 **A（只判不改）**。

## Step① 内部（有依据页）

仍 **先批断、后正文** 两次独立 270s 分发（产品算一步「内容」）：

1. `content.judgment` — 原始批断（可含闭集真词；不打 `⟦t:⟧`）
2. `content.body` — 可见正文：**真·准·可执行·贴收集**（P2=译批断；P3+=可执行扎根）。  
   - **P3**：body **不加厚**；读感归 `body_polish`。  
   - **无 polish 的页**：可见专名仍在 body 步硬闸。

**P1 也两步**：`direct_answer.content.judgment`（path=core_judgment/primary/backup 真算根）→ `content.body`（主辅白话）。产品 UI **仍不挂**依据折层；批断只供生成与 Lab 人审。无 `evidence_soft`。

两枪之间与枪内：**无质量返工链**（仅 JSON 可落库 / 运输级失败可新分发）。落库前 **B 装配**（钉 path/ref/moat 等）；落库后 early 类别机检属 **A（只判不改）**——见上节 A/B/C。

## Step② Phase A → B

- **操作手册（跨会话必遵）**：`交付v3-Lab人审与升闸操作手册.md` — 尤其 **§4 何时建闸 / 如何建闸 / 如何升级**；铁律 `01-delivery-iron` 挂摘要。
- **定调**：起步可几乎无类别闸；Lab **发现问题与建闸同拍**；全流程一遍后基础闸应已立；测稳后收集台持续加厚。
- **Phase A**：最小形状能进预览 + **人审 checklist** + **已挂 early Phase B 类别机检**（**A**：只验不改）。
- **Phase B / 提前升闸**：按故障**类别**加硬尺；禁止 **C**（soft-strip→thin、模板妆合格）。触提前升闸或可机检类别钉死 → 立刻挂机闸，不必等满 N×M。
- **退出账本**：`交付v3-Lab人审失败类别-待冻结闸门清单.md`（N×M + 已升/待）。
- **生产运维（待建）**：Lab 测稳后 → `交付v3-闸门运维收集台-待建.md`。

> Step①「不加质量闸」= **生成枪内**不靠返工装合格；**B 装配**与 **A 验收**分流，见上节。  
> **事实类**闸挂 body；**表面类**（专名/引号/X%）在有 `body_polish` 的页挂 polish 后 full 闸——详见分步职责 SSOT。

## Step②→③ · body_polish（P3 Lab 试点）

仅闸门人审通过后。输入=批准事实稿；输出=用户可见终稿。不过 full 闸 → 不覆盖正文。扩展顺序与合同：`交付v3-正文润色-body_polish-规格.md`。

## Step③

仅 Step②（及 P3 的 polish）通过后解锁。输出展示用依据；正文不动。

## 因果链

任一步未达标 → 禁止推进下一步（含 Lab「本步通过」与生产解锁）。  
**A** 不过 → 回改生成侧，禁止闸门内 **C** 修稿装合格；**B** 盖回不算「闸内修稿」。  
翻车归哪步：`交付v3-分步职责与合格尺-SSOT.md` §3。
