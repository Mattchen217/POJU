## 2. Lab 步进顺序（单页）

有依据页（及 P1）固定：

| 序 | step | 做什么 | 过关条件 |
|----|------|--------|----------|
| 1 | `content.judgment` | 原始批断 | 形状可落库 + **已升闸类别机检** + **人审**（未机检软项） |
| 2 | `content.body` | 白话正文 | 同上（正文侧已升闸类别） |
| 3 | `gate` | Phase A 形状 + 已挂 early Phase B | 机闸过 + 人审其余项；**不过 → 回改提示/喂料重跑 1 或 2，禁闸内改稿** |
| 4 | `evidence_soft` | 依据软译 | **仅** gate 通过后；不改正文 |

**因果链硬**：本步人眼见类别瑕疵 → **禁点「本步通过」**；记类别 → 改生成侧 → 重跑本步；下游标 stale。  
**禁止**带病 unlock 下游「下游再修」。

六页推进：P1 → P2 → P3/P4（可并行深挖，以现行 DAG 为准）→ P5/P6（依赖 P1+P3+P4）。  
**页级喂料白名单（硬）**：见 §2.1；每页只收职责需要的数据，无关块不进 prompt（防污染，不是「去奇门」）。P4 奇门失败 → 本页显式 fail，禁半套降级。

### 2.1 页级喂料矩阵（SSOT · `page-feed-policy.ts`）

| 页 | 总纲/Fact-pack | 奇门锁盘 | 科学菜单 | moat | 处境 surface | 熔断/收束菜单 | 备注 |
|----|----------------|----------|----------|------|--------------|---------------|------|
| P1 | ✓ | — | — | — | — | — | **批断**不灌 collecting；**正文**可灌 reality |
| P2 | ✓ | — | — | — | ✓ | — | 批断薄对照；完整 collecting 偏正文 |
| P3 | ✓ | — | ✓ | — | — | — | +主辅 hint |
| P4 | ✓ | ✓ | — | ✓ | — | — | 双核；禁灌 P3 SOP |
| P5 | ✓ | — | — | — | — | 熔断 ✓ | +上游 action brief |
| P6 | ✓ | — | — | — | — | 收束 ✓ | +上游摘录 |

共享 Fact-pack 若含奇门块：本页 `qimen=false` 时组装后剥净（`stripQimenBlocksUnlessPageAllows`）。

## 3. 人审操作循环（每 dump 一次）

```
用户贴 dump
  → Agent 用「类别」判过/不过（禁只抄本案句）
  → 不过：① 清单追加/核对类别行 ② 主修 duty/喂料/菜单（禁正例照抄）
         ③ 若触「提前升闸」→ 立刻写机闸（见 §4）
         ④ 请用户重跑本步
  → 过：可点「本步通过」；未升闸类别仍靠人审扫
```

**人审结论写法（硬）**：先给一句话 verdict（过 / 不过 + 类别 ID），再列须改的生成侧落点；**不要**把 Lab 原句写进 prompt/正则当唯一拦法。

**「本步通过」含义**：

| 状态 | 含义 |
|------|------|
| 升闸前 | **样本批准**（仅证明本案本次可读） |
| 升闸后 | **样本 + 机闸双过** → 才有生产可迁移性 |

机器闸绿 ≠ 人审过。闸过但人见类别瑕疵 → 仍不过。

## 4. 何时建闸 · 如何建闸 · 如何升级（硬 · 生命周期）

> **产品定调**：P1–P6 起步可以「几乎无质量闸」；**不是**「发现问题也不升」。  
> Lab **一边修一边升**：发现类别瑕疵 → 改生成侧 → **同步**挂/升机闸。  
> **一遍全流程跑通后**，基础闸应已立好一批；之后靠运维收集台持续加厚（见 §8）。

账本与门槛数值：`交付v3-Lab人审失败类别-待冻结闸门清单.md` §0。

### 4.0 三阶段总览

| 阶段 | 何时 | 闸门状态 | Agent/人动作 |
|------|------|----------|--------------|
| **冷启动** | 新页/新步首次 Lab | 仅 Phase A 形状（能预览） | 人审攒类别；主修 duty/喂料 |
| **边修边升（Lab 主航道）** | 每发现可机检类别、或触提前升闸 | early Phase B 类别闸上线 | **发现问题与建闸同拍**（见 §4.1–4.2） |
| **N×M 冻结** | 该步连续 N 次人审过 × M 异盘 | 剩余「待」批量转闸；人审降抽检 | 当日必须冻结，禁「再看几案」 |
| **生产运维加厚** | Lab 主路径测稳后 | 收集台按 `failed_rule` 聚类 | 改 prompt / 升新闸 / 修尺误杀（见运维台文档） |

### 4.1 何时建立 / 升闸（触发）

| 触发 | 动作 | 不必等 |
|------|------|--------|
| 人审首次钉出**类别**（可机检优先） | ① 账本加行 ② 先改 duty/喂料 ③ **能机检则本轮或下一轮挂闸** | 不必等满 N×M |
| **提前升闸**：duty 已钉 + 同盘重跑再中；或 ≥2 attempt 同类别 | **立刻**升机闸（§4.2 动作清单） | 禁止「先通过再说」 |
| 语义难闸（事实同向、backup 拧轴等） | duty 钉死 + 人审；有结构化字段后再升 | 禁止用本案关键词正则冒充 |
| 达 **N×M** | 当日冻结 prompt + 批量转闸 | 禁止无限延期 |

**起点可以无类别闸；终点（全流程一遍）应有一批基础闸**——专名报幕、处境词族、错页奇门、形状 path、已复现怎么办收束等。

### 4.2 如何建立闸门（动作清单 · 只验不改）

1. **类别名**写入冻结清单（禁只贴 Lab 原句当禁表）。  
2. **主修在先**：duty / system / 喂料白名单钉死该类（禁正例照抄、禁案例补丁）。  
3. **机检实现**（类别词族 / 结构检，禁本案二字）：  
   - 批断 → `gate-judgment-category.ts`  
   - 正文 → `gate-body-category.ts`  
4. **接线**：`lab/run-step-v3.ts` 对应内容步 + `gate-phase-a.ts`（汇总 early 类别）。  
5. 清单该行 Phase B → **已升** `gate_*` ID；更新 `types-v3.ts` accept。  
6. 请用户**重跑本步**验证：同类错拦、同类对放。

闸门 **禁止**：改稿、soft-strip、追句 peels、质量空转重试。

### 4.3 如何升级闸门（改尺 / 加类）

| 情形 | 正确升级 | 禁止 |
|------|----------|------|
| 漏放整类 | 扩类别词族 / 加结构检；同步 duty | 只加本案二字 |
| 误杀整类 | 收窄正则或改条件；同步 duty | 为过闸乱砍承重真算 |
| 生产收集台同类达阈值 | 开修 prompt → 必要时加/改 `failed_rule` | 每个 fail 即时热修；自动抽奖重试 |
| 语义类首次可结构化 | 有字段后再从「人审」升「机闸」 | 无字段硬上关键词冒充 |

升级后：**同尺**更新冻结清单 Phase B 列与 accept 文案。

### 4.4 完整冻结（N×M）

默认：**N=连续 3 次人审通过** × **M=3 种差异盘**（禁同一合伙案凑数）。  
达标当日：冻结 prompt 指纹 → 剩余「待」类别批量转闸 → 该步人审降为抽检。

### 4.5 闸门角色（生产同尺）

- 闸门 = **验收尺**，不是质量生成器。  
- 不过 → **显式 fail**；纠错 1+1 仅限同 invoke 未完成稿/可修形状。  
- Step①「不加质量闸」= **生成枪内**不靠闸门返工装合格；Lab/生产可在**生成落库后**跑 early 类别验收（只判不改）。

## 5. 记什么 / 禁什么

| 做 | 禁 |
|----|----|
| 缺陷写成**类别**（换人换盘换题仍成立） | 本案原句进禁表/正则当唯一拦法 |
| 主修 = prompt / 菜单 / claim_seed / 喂料 | 闸内改稿、剥句过闸 |
| 禁区写宏观类别 + 本盘事实约束 | 正例整句照抄、跨案动作范文 |
| 清单「Lab 露出」列仅溯源 | 把露出列复制进 strip |

追句自检：将写进本轮 Lab 二字的 strip/正则 → **停手**。

## 8. Lab 测稳之后（闸门持续升级）

生产失败信号 → `交付v3-闸门运维收集台-待建.md`。  
**分工**：Lab 边修边升把**基础闸**立好；收集台按 `failed_rule` 聚类做**持续升级**（手册 §4.3）。  
**开工条件** = 主路径类别尺已进冻结清单并可拦可记——Lab 未稳前不建收集台冲淡注意力。
