# Pivot · 八页交付验收标准（用户价值尺子）

> **地位**：交付报告质量的 **Canonical 验收标准**。  
> 每次改交付提示词 / 出报告 / 评测交付内容，**必须用本文件衡量是否达标**——是否用户花钱想带走的东西。  
> 与《pivot-全站用户可见输出与五段设计规范》分工：彼文管**怎么说话、怎么算、怎么喂数、五段流程**；本文管**交付写完后值不值钱、护城河在不在**。

最后更新：2026-08-13  
改版依据：交付改版 ①尺子 → ②接算料 → ③药方从命理生长 → ④P4/P5/P6 逐页扎根

## 0. 一句话

用户带走的应是：

> **一份基于我独有命理、告诉我该往哪走 · 怎么走 · 怎么验证的决策方案**

不是：

> 一份关于我性格运势的分析报告 + 谁都能给的通用建议

**护城河落点**：不在 P2「分析你是谁」，而在 **P3/P4「怎么办」——当这个怎么办从命理结构推导、只对他成立时**。药方独有才是护城河；诊断独有只是可信基础设施。

---

## 1. 用户该带走什么（四点尺子 · 按重要性）

带着真实困境（接不接海外 / 去不去创业 / 离不离婚）、花了钱的用户，该带走：

| # | 带走什么 | 反面（不达标） |
|---|---|---|
| ① | **一个清晰的答案**：「以你的情况，我建议走这条，为什么」 | 几条平列选项让他自己挑 |
| ② | **只属于他的理由**：扎在他独有的命理结构上 | 朋友 / 顾问 / GPT 都能复述的泛建议 |
| ③ | **可动手的达成策略**：该守什么、在哪发力、这类人最易栽哪——**命理决策策略**，不替做纯专业执行 | 合同条款 / 完整话术脚本 / 背调流程代做 |
| ④ | **自检信号 + 回来的路**：走出去能对照验证 | 只有鸡汤收尾、无可观察信号 |

四条**全部**成立 → 交付达标。缺任一条 → 未达标（尤其缺 ① 或 ③ 且无命理扎根时，整份报告失败）。

## 2. 全报告通用铁律（每页共用）

### 2.1 删依据自检（护城河尺 · 最高优先级）

对每一条策略 / 调频建议 / 节奏安排 / 避坑提醒：

```text
删掉这条的命理依据（bazi_basis / 折叠「依据与推理」），它还成立吗？
→ 若照样成立（谁都适用）＝没扎命理 → 重写
→ 若不成立（离开他的结构讲不通）＝扎住了 → 通过
```

呼应底座纪律：「删掉依据结论还站得住 = 泛泛而谈」。

### 2.2 生长顺序（诊断与药方都适用）

```text
先：从命理结构（多维 / 用神喜忌 / 忌神盲区 / 大运阶段 / 主辅）推出「对【他】成立」的判断或策略
再：结合用户亲口现实料，落一层可对照的示意（可选，但不能反客为主）
```

**禁止**：先造通用动作 / 通用风水 / 通用注意事项 → 再事后贴命理注脚。

双层用法（现有结构，不叠新注脚）：

| 层 | 字段 | 职责 |
|---|---|---|
| 策略 / 结论正文 | `core_conclusion` → main_body | 白话决策策略 / 论证 / 节奏（零裸命理词） |
| 命理依据 | `bazi_basis` → 折叠依据层 | 闭集真词；**依据前置**——先有依据推出正文，不是事后标签 |

### 2.3 给什么 · 不给什么（策略页硬判据）

| 给 ✅ | 不给 ❌ |
|---|---|
| 决策边界 / 发力点 / 该类结构易栽点 / 主辅切换条件 | 合同条款、完整话术脚本、专业流程代做 |
| 一层「第一步怎么起」的场景示意（用用户亲口料锚一下） | 整段执行剧本（「周三约老板，这样开口说…」铺满） |
| 基于命理、只对他成立的策略骨架 | 「注意休息 / 别熬夜 / 多沟通」等谁都适用的空话 |

### 2.4 表达与合规（与全站 Canonical 对齐）

- 正文：行为 / 精力 / 决策白话 + 受控映射；禁裸命理专名报幕。  
- 依据层：闭集 `⟦t:slug|软译|语境⟧`；渲染走 `GlossaryText` → `RichReadingText`。  
- 不报具体日期点位；时机 = 阶段趋势 + 条件成熟。  
- 禁命运定论、伪医疗、吉凶风水属相字面。  
- 跨页：「养根 / 小森林 / 宜守向内」主隐喻全报告 ≤1 次（只许落在 foundation）。

## 3. 逐页达标标准（P1–P8）

结构不推倒。每页必须完成该页信息维；**决策向页（P2–P6）必须命理扎根**。

| 页 | 键 | 用户带走 | 达标判据 | 主要上游料 |
|---|---|---|---|---|
| **P1** | `direct_answer` | ① 清晰答案 | 正面直答 original_question + 一句主路径「我最建议走这条」+ 一句为什么；**只给结论头**，不铺论证；禁止平列多选让用户自己挑 | `situation_conclusion` + `primary_path` + desired_outcome |
| **P2** | `foundation` | ② 为什么卡（可信桥） | 从**多个命理维度**论证「为什么卡」；每维可作依据；收敛到「所以你卡在这」；删依据后论证垮掉 | `energy_structure` + `multi_dimension_reckoning` + 命局基础 |
| **P3** | `science_action` | ③ 怎么办（**护城河核心**） | 策略从多维 + 主辅 **生长**（非事后贴标签）；给边界/发力/易栽/切换；允许一层第一步示意；禁执行剧本；删依据不成立 | `primary/backup` + `action_plan` + `multi_dimension_reckoning` + 收集证据 |
| **P4** | `metaphysics_action` | ③ 专属环境调频 | 方位/色彩/时段/贵人从**用神喜忌、五行**推出（缺什么补什么）；不是通用风水；删依据不成立 | `metaphysics_pack` + `energy_retune_frame` |
| **P5** | `thirty_day` | ③ 落地节奏 | 四周松紧对应**当前大运/阶段**（宜守 vs 可推进）；禁止把 action_plan **平均切 4 段**；按周不按天 | `rhythm_frame` + `action_plan` + `current_da_yun_cycle` |
| **P6** | `risk_guard` | ③ 避坑安心 | 坑是**该类结构特有**的（忌神 / 性情盲区）；不是「别熬夜」通用提醒；删依据不成立 | `self_check` 负向 + `ji_shen` + `blind_spots` |
| **P7** | `signals_close` | ④ 自检可出发 | 正向可观察信号 + 一次性闭环「你已拿到完整打法」；**禁止**回来追踪 / 订阅钩子 | `self_check` 正向 |
| **P8** | appendix | 透明存档 | 结构数据 + 术语说明；不承担决策叙事 | structured / 闭集说明 |

**P2 与护城河**：P2 不是产品命脉，但是药方的**可信基础设施**——没有扎根的诊断，P3「对你成立」无处落地。验收时 P2 必须扎实，但价值兑现仍以 P3/P4 为主。

## 4. 算料接线标准（没有料，改要求是空的）

交付 finalize **必须吃到**重构后的算料（改版②）。缺料时允许降级丰富度，**不允许**放弃「从命理生长」原则。

| 料 | 必须进哪些页 | 缺失时 |
|---|---|---|
| `multi_dimension_reckoning` | P2、P3 | P3 退回主辅 + 脊柱锚推策略；仍禁止先造通用动作 |
| `action_plan`（synthesis） | P1/P3 展开、P5 排节奏 | 用 `primary/backup` + frames 兜底 |
| `primary_path` / `backup_path` | P1、P3、P5 | 读 `modern_action_frames` |
| `metaphysics_pack` | P4、P5 表、P6 忌神 | 薄写并标明依据不足；禁编数字/方位 |
| `current_da_yun_cycle`（逻辑字段） | P5（及 P2 周期论证） | 用 `timing_ripeness` + rhythm；仍禁止平均切周 |
| `covered_agenda` | P3 一层示意、现实校准 | 不编造人名/项目/数字 |

- 切片清单：`lib/llm/pro/delivery/delivery-schema.ts` → `SEGMENT_COMPUTED_INPUTS`
- dump：`lib/llm/pro/delivery/format-spine-for-finalize.ts`

## 5. 单次交付验收清单（出报告后逐项勾）

### 5.1 用户价值（必过）

- [ ] **① 答案**：P1 有明确主路径建议，不是菜单式多选  
- [ ] **② 独有理由**：P2/P3 依据层有真实盘面锚；删依据后关键判断垮掉  
- [ ] **③ 策略可动手**：P3 有边界/发力/易栽/切换；有至多一层第一步示意；**无**合同/话术剧本/专业代做  
- [ ] **④ 自检**：P7 有可观察正向信号；无回来追踪钩子  

### 5.2 护城河（决策向页必过）

- [ ] **P3**：策略能对应到多维某维和/或主辅；生长顺序 = 先命理后示意  
- [ ] **P4**：方位/色彩能说清「对【他】有用」的用神/五行根由  
- [ ] **P5**：四周松紧有阶段依据，非平均切  
- [ ] **P6**：坑是结构特有，非通用注意事项  
- [ ] 以上任一条：删 `bazi_basis` / 依据折叠后仍「谁都适用」→ **该页不通过**  

### 5.3 工程与表达（必过）

- [ ] 八页齐全；跨页去重（养根类隐喻 ≤1）  
- [ ] 正文零裸命理专名；依据层闭集打标正确  
- [ ] 渲染走 Glossary / RichReading；落库过 audit  
- [ ] 无命运定论、伪医疗、吉凶风水属相字面  

任一项「用户价值」或「护城河」失败 → **整份交付不达标**，不得以「文笔好 / 页数齐」放过。

## 6. 三盘对照（改提示词 / 大改交付后必跑）

选三个**差异大**的困境盘（如职场 / 创业 / 感情，且命理结构明显不同），各出一份报告：

| 对照项 | 通过条件 |
|---|---|
| 药方不雷同 | 三盘 P3/P4/P6 策略与坑明显不同（不是换皮同一段） |
| 删依据不成立 | 每盘决策向页抽查：去掉命理依据后策略垮掉 |
| 无替做执行 | 无合同条款 / 完整话术 / 专业流程代做 |
| 无通用模板 | P4 非通用风水；P5 非平均四周；P6 非「别熬夜」 |
| P2 不被破坏 | 仍从多维论证「为什么卡」，与 P1 结论头不重复灌水 |

三盘对照失败 → 回滚或重修对应页提示词，不得标「改版完成」。

## 7. 改交付时的纪律

1. **先接料、后改要求**（②→③→④ 顺序不可倒）。无多维 / action_plan 却要求「从多维生长」= 空转。  
2. **用现有双层**（`core_conclusion` + `bazi_basis`），不叠「Profile basis」类事后注脚。  
3. **交付向规则只进交付层**（finalize / narrative / evidence / 该阶段 taskBlock）；禁止灌进 `POJU_IDENTITY*` 或无门控控制面（见《提示词按阶段隔离》）。  
4. **评测口径以本文为准**；文风 / 闭集 / 五段流程仍服从全站 Canonical。

## 9. 最短判词（给评审人）

打开一份交付，只问三句：

1. **他带走的是「该往哪走的决策方案」，还是「关于他的分析文章」？**  
2. **删掉命理依据，P3/P4/P6 还成立吗？**（成立 = 失败）  
3. **有没有替他做了律师 / HR / 顾问才会做的执行剧本？**（有 = 失败）

三句过 → 才是用户花钱想要的东西。
