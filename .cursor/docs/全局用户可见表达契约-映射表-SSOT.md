# 全局用户可见表达契约 + 映射表 SSOT

> **定位**：东方系统内核（引擎真算）+ 现代行为/精力语言（用户可见）+ 闭集受控映射（可审计）。  
> **不是**：消灭一切东方痕迹，也不是把每句都写成伪医学检测报告。  
> **与** `.cursor/docs/pivot-全站用户可见输出与五段设计规范.md` **分工**：该文件是全站/五段 Canonical（含闭集/双层/底座）；**本文件专管映射行与表达契约细则**。

最后更新：2026-08-12

## 1. 全局用户可见表达契约（Contract）

### 1.1 目标（Goals）

1. **零认知摩擦**：美国高中～白领能读懂；不依赖丑时/十神/生克四字格常识。  
2. **护城河留在引擎**：判断仍锚 `structured` 与真算骨架，禁止为了好听而编科学故事。  
3. **品牌不失东方**：允许克制的系统隐喻（energy structure / base configuration / rhythm）；允许拼音品牌调味（`QI` · `BAZI` · `WUXING`…）且**首次附英文 gloss**。  
4. **非医疗 / 非占卜**：可讲「常见压力与恢复模式」框架，**禁止**装作已测皮质醇/已做临床诊断；禁止定命事件与具体日期点位预测（见 `output-policy`）。

### 1.2 铁律（Hard rules）

| ID | 规则 |
|---|---|
| C1 | **用户可见正文**禁止裸命理专名：十神原名、干支连写（如「壬水」）、十二时辰专名（子丑…）、生克四字格、神煞原名、大运/流年/命盘/八字等（完整禁表与审计仍以 `banned-terms` / 四产品规范为准）。 |
| C2 | 凡从引擎得出的判断，用 **「系统/精力依据感 + 可观察结论」** 说：依据感前缀限能量类（energy base / energy structure / innate configuration / underlying pattern）；结论必须可感、可行动，且**真对应**骨架/`structured`（禁套壳安慰）。 |
| C3 | **科学词是翻译，不是新算一层医学**。映射表未覆盖的概念 → 行为/决策白话，**禁止**临场发明「皮质醇/交感神经」故事。 |
| C4 | 映射输出须可追溯：每条用户可见判断能指回引擎侧字段或维度 judgment；指不回 = 删。 |
| C5 | **伪医学红线**：不写「你的皮质醇检测显示…」「确诊…」「处方药级建议」；可用「在长期高压下，很多人会出现…这类恢复系统报警信号」一类**框架性**说法，且不替代就医。 |
| C6 | **阶段隔离**：本契约约束「用户可见层」。L0 真算腿（DIMS/SPINE）可继续裸词；**禁止**把 ⟦t:⟧ / 双层交付排版灌进身份层或全阶段控制面（见 `08-prompt-phase-isolation`）。 |
| C7 | 拼音品牌词 ≠ 泄漏：`BAZI (birth chart)` 等允许；「你的八字里湿土…」不允许。 |

### 1.3 语气与可读性

- 默认 **Plain American English**（产品主语言）；中文 locale 用同等白话，仍禁裸命理专名。  
- 克制、有锋利、少疗愈腔；温度来自说得准，不来自复读用户。  
- 优先：决策结构 / 精力节奏 / 关系负载 / 环境负荷 / 可观察信号。

### 1.4 反例（不合格）

| 反例 | 为何不合格 |
|---|---|
| 「丑时湿土本应收敛」 | 裸时辰+五行；美国用户零基底 |
| 「火旺木焚所以你该…」 | 四字格报幕；无行为机制 |
| 「你的皮质醇在 3:00 异常飙升（已确认）」 | 伪检测；越权医疗 |
| 「从命盘看你注定…」 | 占卜/定命 + 禁词 |
| 全篇抹掉东方、只剩通用鸡汤 | 丢掉产品差异与可追溯性 |

### 1.5 合格方向（示意 · 非填空范文）

引擎判断「夜间某时段易醒 + 燥热消耗」→ 用户可见可写成：长期高压下，恢复窗口被压缩，夜间大脑像被提前「强制开机」——这是精力恢复系统的报警，不是单纯「睡得不好」；接下来要对齐的是如何强制降温与重建恢复节奏。  
（机制框架 + 可观察 + 推进；不报丑时、不伪造化验单。）

## 2. 映射表 SSOT

### 2.1 权威位置

| 形态 | 路径 | 用途 |
|---|---|---|
| **文档 SSOT（本文件 §2.3）** | `.cursor/docs/全局用户可见表达契约-映射表-SSOT.md` | 产品/提示词评审、扩展映射时先改这里 |
| **代码 SSOT** | `lib/glossary/vernacular-mapping-ssot.ts` | 供后续 prompt builder / 测试 / 审计引用；**与本表行级对齐** |

扩展映射：**先改文档表 → 再改 TS 常量 → 再挂阶段引用**。禁止各阶段私建第二套软译表。

### 2.2 映射字段说明

每条映射：

- `engine_concept`：引擎/骨架侧概念（中文或内部标签）  
- `user_facing_en`：默认英文可见语（行为/精力/决策）  
- `user_facing_zh`：中文 locale 可见语  
- `allowed_frame`：允许的解释框架标签（如 `stress_recovery` / `decision_load`）  
- `never`：禁止连带出现的伪医学/定命说法  
- `trace`：应能追溯到的典型引擎锚（字段或维类型，示意）

## 3. 阶段挂载图（哪里引用 · 哪里禁止）

遵循 `08-prompt-phase-isolation`：**交付向打标/双层绝不进恒在身份层**；本契约的「用户可见白话」可进各阶段 **taskBlock**，完整映射表优先 **按需注入**（避免撑爆静态 system / 破坏 prefix cache）。

| 阶段 / 调用 | 挂载？ | 挂法建议 | 说明 |
|---|---|---|---|
| **L0 DIMS**（`segment2-a-parallel` dims） | ❌ 不挂可见契约 | — | 内部真算，允许裸词 |
| **L0 SPINE** | ❌ | — | 内部骨架，允许裸词 |
| **VOICE**（Call A voice / `DEEP_RECKONING_VOICE_TASK`） | ✅ **必须** | taskBlock 注入契约摘要 + 映射表子集（stress/decision 相关行） | 用户可见长文；禁流水账裸词；科学词须在表内 |
| **Call B 议程/首问**（`AGENDA_BRIDGE_TASK`） | ✅ **必须** | 契约摘要（可见语 + 反例）；映射表可短 | label / first_question / options 全是用户可见 |
| **collecting**（`POJU_V6_COLLECTING_PHASE_RULES` + taskBlock） | ✅ **必须** | 契约摘要并入「response 文风」；一般不灌全表 | 对话可见；少共情、禁裸词 |
| **opening** | ✅ **必须** | `buildOpeningTaskBlockV6` 注入 `preset: "opening"`（摘要、不灌全表） | 仅 response / options 可见 |
| **confirmation** | ⚠️ 摘要可选 | 与 opening 对齐即可；未强制挂全表 | wrap-up 可见句仍靠 autoMark 兜底 |
| **synthesis** | ✅ **必须** | `buildSynthesisPrompt` → `preset: "synthesis"` | direction / why_fits / action_plan 白话；structural_basis 可内部锚 |
| **delivery finalize / narrative / mark** | ✅ **分层** | **正文/body**：契约 + 映射；**依据与推理**：走四产品闭集 `⟦t:⟧`，**不适用**「永不出现术语」 | 双层：正文科学/行为语，折叠层可金字 |
| **POJU_IDENTITY / 无门控控制面** | ❌ 不灌全表 | 最多一句定位指针（「用户可见遵循表达契约」） | 防污染 + 护 prefix cache |
| **output-policy / banned-terms** | ✅ 协同 | 契约引用它们作审计底线；映射表不取代红线 | 合规行为层仍最高 |

### 3.1 推荐注入形态（实现时）

```text
buildUserFacingExpressionContractBlock({ locale, mappingRowIds?: string[] })
  → 短契约（Goals + C1–C7 压缩）
```

- VOICE / Call B：`mappingRowIds` = 与问题类型相关的子集

- delivery evidence：不注入本契约的「禁术语」条款，改走四产品标记规范

## 7. 泄漏回流：禁词 → 频发升格映射行

目标：映射表**靠真实泄漏变齐全**，不是一次性抄全闭集。

```text
purity / audit 命中
  → recordUserFacingLeakHit（进程内 ring + [vernacular-leak] 日志）
  → 评审后写入 STAGED_BAN_ZH（vernacular-leak-staging.ts）
       → delivery-body-purity 立即拦截
  → 同一概念累计 ≥ LEAK_PROMOTE_TO_MAPPING_THRESHOLD（默认 3）
       → suggestLeakPromotions / formatLeakPromotionReport
       → 人工起草映射行：先改本文件 §2.3 → vernacular-mapping-ssot.ts
       → 挂入对应 EXPRESSION_CONTRACT_MAPPING_IDS preset
       → 从 staging 移除已进 BANNED_TERMS / 已有映射的重复项
```

| 代码 | 职责 |
|---|---|
| `lib/glossary/vernacular-leak-feedback.ts` | 记录、聚合、升格建议、报告模板 |
| `lib/glossary/vernacular-leak-staging.ts` | 待并入正式禁表的 staging 禁词 + 映射草稿槽 |
| `warnDeliveryProsePollution` / `auditDeliveredText` | 命中时自动 `recordUserFacingLeakHit` |

**铁律**：回流只改 staging / banned-terms / mapping SSOT / 阶段 preset——**永不**把升格结果写进 `POJU_IDENTITY`。
