## 1. D1 要解决什么（落地前诊断）

### 1.1 旧架构（漏桶）

```
模型自由看库存/真算 → 自选 slug + dimension → 写 role/why/inference
        ↓
多层闸门挑错 / soft-strip 剥空 / LLM 纠错重试
```

典型失败（换盘表面不同、根因同类）：

| 类型 | 例子 reason |
|------|-------------|
| 选词非法 | `slug_not_in_thesis` / `slug_wrong_dim` / `slug_bare_ganzhi` / `changsheng_parked` |
| 影子池 | 金舆等神煞未进总纲仍承重 |
| 页内撞车 | `anchor_reuse_jaccard:1.00`（两卡同主词） |
| 剥空 | `thesis_gap:soft_strip_empty:…` |
| 推理违规 | `third_party_attr`（用本盘推第三者动机） |
| 空转 | 质量失败仍 LLM 重试；预算不够 → `skip in-process retry` |

**结论（当时拍板）**：闸门只会「挑错」，不会「生成正确答案」。开放选词下，换盘覆盖更广命理组合 → 新错误模式无穷。应把合法性前移。

### 1.2 D1 目标架构

```
ChartThesis (present 事实)
    → buildThesisAssignMenu          【代码】仅可验词核
    → preallocateFoundationSignals   【代码】每卡锁 slug+dimension
    → LLM 只写 role / why / inference_zh（+ 润色 claim/cite）
    → 窄闸（推理质量）+ 确定性软修
```

| 层 | 谁做 | 产出 |
|----|------|------|
| 菜单 | 代码 | `(dimension_id, slug, fact_hint)[]` |
| 预分配 | 代码 | 每 `why_cards[i]` 恰好 1 个 `locked_signals`；页内主词唯一 |
| 模型 | LLM | 解释文字；禁止改 slug/维/条数 |
| 闸门 | 代码 | slug≠预分配 → 硬失败；保留 third_party 等推理闸 |

**明确不做（D1）**：扩神煞/长生进总纲；一次切完 P3–P6；Lab-only 双路径；用软修编造整段假推理。

- 观测：closed-menu 后 input/output token 明显下降（只写解释、不逛大库存）——属预期收益。

## 3. 落地后遇到的问题与解法

按时间线与根因归类。**解法栏标明是「全局类修」还是「症状补丁」**。

### 3.1 选词 / 结构（D1 主目标）— **已闭合，停止投入**

| # | 现象 | 根因 | 解法 | 性质 |
|---|------|------|------|------|
| 1 | `slug_not_in_thesis` / `wrong_dim` | 模型自选未验词或标错维 | 菜单按维出词；locked 强制 dim | **全局** |
| 2 | 神煞/长生影子池 | 库存含未扩维词 | 菜单不进；prefer/inventory thesis 过滤 | **全局** |
| 3 | `slug_bare_ganzhi`（如裸「癸」） | 半成品承重 | 菜单禁单干支 | **全局** |
| 4 | `signal_count_mismatch` | 模型声称 N≠实际 | 每卡固定 1 槽 + overwrite 对齐 | **全局** |
| 5 | `anchor_reuse_jaccard` | 多卡同主词 | 预分配页内唯一；Jaccard 软修兜底；禁 LLM 重试 | **全局** |
| 6 | `soft_strip_empty`（非法词剥空） | 先自由选再剥 | Closed 路径不再依赖 strip 非法 slug | **全局** |

**验收（盘1）**：`primaries: [巳寅相刑, 比肩, 正财, 六合, 金]`，`assign ok (closed-menu)`，非法选词类 reason 不再出现；五卡主张与「删依据会垮」自检过。

**产品确认**：这一层靠「代码预分配、模型只填推理」消掉，与总纲六维「确定性先做、模型填空」同构。**不要再为这六类现象加规则/扩菜单打地鼠。**

### 3.2 工程 / Lab 体验

| # | 现象 | 根因 | 解法 | 性质 |
|---|------|------|------|------|
| 7 | Fail 时 OUTPUT_TO_NEXT=`null` | fail 路径故意不吐稿 | 挂 `{ _gate, reason, rejected_draft }` | **全局** |
| 8 | `skip in-process retry` 警告 | 质量失败仍想 LLM 重试且预算不足 | Jaccard/closed 质量失败改软修或 break；警告本身是护栏 | **全局** |
| 9 | Token 变少 | Closed 后任务变窄 | 不修；属架构收益 | — |
| 10 | TS build：`alloc.reason` on `never` | assert 收窄不当 | 测试先 `if (!ok) throw` | 工程 |

### 3.3 推理质量（D1 收窄后仍会爆）— 当前主战场

D1 **故意**把剩余问题收成「合法词上的推理文」。这类**随盘面与表象变化**，不是选词 bug。

| # | 现象 | 根因 | 已做解法 | 局限 |
|---|------|------|----------|------|
| 11 | `third_party_attr:…伙伴…期望`（金舆/盘1 类） | 解释层用本盘推第三者意愿 | 正则闸（主语×意愿词）+ 确定性软修改写盘主视角 | 意愿词表**有限**；金舆那次甚至曾缺对应检查 |
| 12 | 软修叠句「你感到你在该结构下更易感到」 | 套话替换叠在模型原句上 | `collapseQuerentPressureStutter` + 语境替换 | 可过闸，文风仍可能板 |
| 13 | `unit_claim` =「此表象说明结构上：」+原句 | 模型偷懒粘贴 | Prompt 禁止 + 薄主张软修 | 模板感 |
| 14 | 盘2卡3「男友…反对」 | **同构**：第三者作态度施事；「反对」不在 volition 词表 | **禁止**加「反对」一词针对修 | 见 §4 |

**两案对照（表面同、穿闸原因不同）**：

| | 金舆 / 伙伴期望类 | 盘2 男友反对 |
|--|-------------------|--------------|
| 语义 | 用户盘信号 → 解释第三者心理 | 同左 |
| 穿闸原因 | 闸门一度**无**对应规则，或规则形状不够 | 闸门**有** `third_party_attr`，但依赖意愿动词词表，**「反对」未入表** |
| 共同本质 | **开放自然语言生成 × 有限关键词闸门** — 表达花样快于枚举 |

**盘1（乙木/创业）肉眼签**：选词层 + 该稿推理可过。  
**盘2（焦虑/男友）闸门绿、肉眼否**：卡3 `子未相害` →「导致男友…强烈反对」。

### 3.4 关键认知（避免再踩）

1. **闸门绿 ≠ 肉眼合格**（盘2已证）。  
2. **盘1合格 ≠ 换盘合格**：合格的是「那一稿」；全局保证靠规则形状，不靠样本记忆。  
3. **D1 成功域**：选词合法性、条数、撞车、影子池 — **已闭合**。  
4. **当前失败域**：开放句式把命理接到人生表象时的第三方归因等 — **换检测对象 + 主张槽，不是补词表**。  
5. **禁止**：为盘2加 `if (男友|反对)`；那是针对修，与 D1 初衷相反。

## 4. 为何「现在这套」仍难扛多样性

```
多样性来源拆开：

  盘面多样性     → 总纲菜单可承载（D1 已做 · 闭合）
  表象多样性     → 收集菜单可承载
  解释句多样性   → 开放 LLM 句式 × 第三者/因果/语气 → 组合爆炸（未锁死）
```

当前 assign 仍让模型输出**完整自然语言推理**。闸门若用「主语×意愿词表」：

- 词表永远短于自然语言；  
- 每补一个词（期望→反对→催促→不满→抵触→不太乐意…）都是打地鼠；  
- 与「开放选词 + 后置闸」同构，只是问题从 slug 挪到了句子。

**因此**：不是「P2 assign 选词做不好」，而是 **「在 assign 里保留开放推理生成 + 词表闸」与「换盘稳定」目标冲突**。要换的是**链路自由度与检测对象**，不是再加一层意愿动词。

## 5. 换链路方案（拍板版）

原则：**多样性落在有限组合（总纲主张 × 表象类型）上，不落在开放句式上；检测落在「已知第三方是否施事」，不落在「意愿动词枚举」。**

### 5.1 方案 A — 主张槽绑定（主路径 · 方向确认）

**一句话**：Assign 绑定的是「总纲已审主张 ID」，不是「让模型现场写整段推理」。

```
thesis present 事实
  → 每条带 claim_seed（summary / usable_claims 定稿句）
  → 表象分类 surface_class【代码】
  → 路由：surface_class × dim → 选 claim_id + locked slug
  → 关系摩擦类：走 §5.3 固定句模（焊死）
  → 其余类：字段拆开填空（相对自由）
```

**输出形状建议：**

```json
{
  "mechanism": "六合化金加重官杀约束",
  "querent_effect": "你更难开口提兼职试水"
}
```

第三者只允许出现在 `calc_cite` 表象引用，不进入解释层作施事。

| 优点 | 代价 |
|------|------|
| 换盘稳定；与 D1 菜单连续 | 总纲侧要产出/维护 claim_seed |
| 删依据可追溯到总纲句 | 文风先稳后润 |
| 缩小开放句自由度 | 表象分类器要做对 |

---

### 5.1b 方案 A 的结构性漏洞（必须先补，否则会再撞一次）

**漏洞**：强制 `querent_effect` 语法主语是「你」，**不能**保证语义上没在断言第三者心理。

反例（结构合规、语义违规）：

> 「你让男友对你产生了强烈的抵触情绪」

- 语法主语 =「你」→ 过「主语必须是你」检查；  
- 实质 = 断言男友情绪/态度 → 与「男友强烈反对」同构。

若落地 A 却只做字段主语检查，**连字段结构这道防线都会形式上合规**，更难查。

**补丁（检测换对象 · 拍板）**：

| 旧判定 | 新判定 |
|--------|--------|
| 扫描解释文字里有没有「反对/期望/催促…」等意愿动词 | 检测：**agenda 已锁定的具体第三方**，是否在解释文字里成为**某个谓语的施事者** |
| 开放质量感 / 词表扩 | 边界清晰的结构判断题：谁是动作主体 |

**实现要点**：

1. **第三方闭集来源**：本次咨询 `covered_agenda` / 用户原问里出现的称呼（男友、旧部、老板、伙伴…）— 已知、有限、可抽取。  
2. **判定**：该称呼是否在 `mechanism` / `querent_effect` / `inference_zh` / `role` / `why_needed` 中充当动作施事（「男友做了/感受了什么」），**不**猜用了哪个意愿动词。  
3. 「反对 / 抵触 / 不太乐意 / …」任意说法，只要是「已知第三方作施事」→ 抓。  
4. 允许：表象引用里出现第三方名字；禁止：解释层让其作施事。  
5. **不是**再扩意愿动词表；旧词表闸可降级为辅助或逐步退役。

这与「结构主语必须是你」**叠加**，不互相替代：主语规则防「男友反对」直写；施事者规则防「你让男友…抵触」绕写。

### 5.3 方案 C — 句模：按风险分层（修订定位）

**不再**仅写「并入 A 当填充策略」。改为：

| surface_class | 防御 | 理由 |
|---------------|------|------|
| **关系摩擦**（伴侣/家庭/同事上下级等） | **最严固定句模（C）焊死** | 第三方归因风险几乎全集中于此 |
| 资源 / 精力 / 时机窗口等 | **A 式填空**（mechanism + querent_effect） | 低风险；不必全局模板腔 |

例（关系摩擦类焊死句模骨架）：

> 「{cycle_token} 使你在亲密关系议题上更易感到推进阻力；张力并存时，压力落在你侧的开口与节奏上。」

高风险处绝对安全；其余保留一定表达自然度。
