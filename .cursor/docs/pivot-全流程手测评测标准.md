# Eastern OS（Pivot）· 全流程手测评测标准

> **用途**：你在产品里设计若干真实问题，从 Stage1→4（含可选 Companion）逐段对照本表打分。  
> **配套**：交付页细尺见 [`pivot-八页交付验收标准.md`](./pivot-八页交付验收标准.md)；合盘/双路径 SSOT 见 [`pivot-p0-p3-真算与合盘取舍.md`](../plans/pivot-p0-p3-真算与合盘取舍.md)。  
> **产品名**：用户可见一律 **Eastern OS**；工程模块可仍叫 Pivot。  
> **主问**：始终「围期望 · 你怎么破」。双盘只加依据，不做 Match 全页翻版。

最后更新：2026-10-13

## 0. 怎么用这份标准

### 0.1 建议用例矩阵（至少跑齐）

| # | 用例类型 | 题干设计要点 | 期望 path |
|---|----------|--------------|-----------|
| A | 非二元 · 事业/决策 | 只有「我」的困境 + 明确期望（如接不接项目、要不要转行） | `solo` |
| B | 二元 · 收对方盘 | 与**某一个**具体他人（伴侣/合伙人）+ 期望；点「输入对方基础信息」 | `dyad` |
| C | 二元 · 跳过对方盘 | 同上议题；点「暂时不输入」 | `solo`（有二元门信号但无对方盘） |
| D | 三人及以上 | 「我与 A、B、C…」或家庭/团队多人同时要合盘推演 | **拒识引导**，不进伪多元真算 |
| E | 「你是谁」 | 开场或中途直接问身份/能力 | 答 Eastern OS；不提 Pivot；不编造未承诺能力 |

每条用例建议记录：`题干原文` · `是否进二元门` · `锁盘 path` · `各段截图/粘贴` · `总分` · `致命否决项`。

### 0.2 评分尺度（统一）

| 分 | 含义 |
|----|------|
| **2** | 明确达标 |
| **1** | 部分达标 / 有可接受瑕疵 |
| **0** | 未达标 |
| **X** | 致命否决（见各段「一票否决」）→ 该段整段失败，不必再加分粉饰 |

**段通过线**：该段无 X，且平均分 ≥ 1.5（或你自定义门槛）。  
**全案通过线**：A/B/C 至少各 1 条无 X；D/E 行为正确；交付段对照八页标准无致命项。

### 0.3 评测时看什么界面

| 阶段 | 主要看 |
|------|--------|
| Stage1 | 聊天回复、理解门摘要/确认、二元二选一芯片、对方生辰框 |
| Stage2 | 多维观察回复（Call A 对用户可见部分）、议程首问（Call B） |
| Stage3 | 收集追问、芯片选项、是否闲聊跑题、确认收口 |
| Stage4 | P1→P6 渐进展示、每页判断/正文、主辅与期望对齐 |
| Companion | 日提醒是否单人流日；dyad 时 Brief 关系栏杆（若有） |

## 1. Stage1 · 理解门 + 路径锁定

**设计目标**：摸清「主问题（单楔）+ 情况 + 主期望」；二元题出示收盘门；确认后**锁死** `solo|dyad`；不深算、不定主辅、不灌交付。

### 1.1 身份与能力边界

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S1-ID-1 | 问「你是谁」时自称 **Eastern OS**（东方决策操作系统/决策模型口径） | 提 Pivot / 编造算命恐吓能力 = **X** |
| S1-ID-2 | 说明能力范围：单人 或 二人二元；药方落用户可执行侧 | |
| S1-ID-3 | **三人及以上**合盘/多方同时推演 → 明确拒绝 + 引导收成「只谈我」或「我与某一个具体人」 | 进入伪多元真算 = **X** |
| S1-ID-4 | 声明不是心理/法律/医疗替代；不恐吓式占卜 | 恐吓命运断言 = **X** |

### 1.2 理解门内容质量

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S1-U-1 | **单楔**：主问题收敛到一件具体事，不把三件独立事绑死 | 多楔并行当「已够」硬推 Stage2 = **X** |
| S1-U-2 | **情况**有实质（时间/角色/约束），非空话复读用户原句 | |
| S1-U-3 | **期望**被主动问清，且对准主楔（不是「变得更好」空期望） | 未问期望就宣称足够 = **X** |
| S1-U-4 | 不展开整段命盘分析、不定「主路径/辅路径」、不产议程清单 | 提前交付/定主辅 = **X** |
| S1-U-5 | 每轮有推进（新观察或对准缺口的追问），非原地复读开场 | |
| S1-U-6 | 理解门确认 UI：确认 / 补充 语义清晰；确认后才进 Segment2 | offered 未结案就进 Stage2 = **X** |

### 1.3 二元收盘门与 path 锁定

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S1-D-1 | **非二元题**：不无故弹出收对方盘（或合理不弹） | |
| S1-D-2 | **二元题**：出现固定说明 + 二选一（输入对方 / 暂时不输入） | |
| S1-D-3 | 选「输入」→ 工作台生辰框；成功后 `path=dyad`，有 summary + matrix 锁盘感（后续更准的承诺兑现于 Stage2/交付） | 无对方盘却后文编造对方八字 = **X**（可在后段判） |
| S1-D-4 | 选「跳过」→ `path=solo`，文案仍承诺围期望给完整交付 | |
| S1-D-5 | `offered` 未点芯片时**不能**闷声进 Stage2；应 skip 结案或强制选择 | 未结案进 Stage2 = **X** |
| S1-D-6 | 跳过/收集后续聊天气泡不卡死（有忙碌反馈，能继续） | |

### 1.4 Stage1 段评语模板

```
用例：__  path：solo|dyad|拒识
身份：__/2  理解门：__/2  二元门：__/2
否决项：无 / 列出
总评：通过 / 不通过 · 一句话
```

## 2. Stage2 · Call A（多维真算）+ Call B（议程）

**设计目标**：  
- Call A：把相关命理维度算全、各出判断；**不收敛主辅**；用户可见是多维观察，不提问。  
- Call B：按「交付倒逼」起草议程；solo 围主盘+问题；dyad 必覆盖角色/权力、可观察行为、你的底线。  
- **不**在 Stage2 产出独立「关系批断交付物」/ Match 章节墙。

### 2.1 Call A · 对用户可见回复

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S2-A-1 | 紧扣 Stage1 的问题 / 情况 / **期望**，不是泛性格报告 | 离题空谈 = 0；完全无视期望 = **X** |
| S2-A-2 | **多维**：至少多个不同结构轴（用忌/岁运/宫位/十神等），非单点深挖用户当前手段 | 只围「当前那个项目」打转且无结构 = 0 |
| S2-A-3 | **不收敛**：不出现「我最建议你走这条主路径/辅路径」定案口吻 | 提前定主辅当交付 = **X** |
| S2-A-4 | **不提问**（议程问题留给 Call B / Stage3） | 大段问卷式连环问 = 0 |
| S2-A-5 | 合规：适配/阻力表述；无「你命中注定/必败」恐吓 | 恐吓断言 = **X** |
| S2-A-6 | **dyad**：能感到「双方机制/张力」挂在真算上，但收敛到**你侧**处境；无合盘分数墙、无对方大运编造 | 无对方盘却写对方日主大运 = **X**；Match 专章墙 = **X** |
| S2-A-7 | **solo / 跳过二元**：明确不臆造对方命理；他人仅作自述角色 | 臆造 = **X** |

### 2.2 Call B · 议程与首问

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S2-B-1 | 议程条目**对解题/期望有用**，非闲聊备料 | 纯寒暄题当 critical = 0 |
| S2-B-2 | 条目可映射到后续交付缺口（资源/节奏/约束/验证等），看得出「报告缺什么才问」 | |
| S2-B-3 | **dyad 必覆盖三类**：对方角色/权力位；可观察行为/态度；你的硬底线（可分散在多条） | 缺整类 = 0；故意不问关系现实却写二元药方 = **X**（后段交叉） |
| S2-B-4 | **solo**：不强迫收「对方八字」；二元跳过案可用「你观察到的对方行为」而非命理 | |
| S2-B-5 | 首问清楚、选项芯片可用（若有）；问题像解题对齐，不像性格测试 | |
| S2-B-6 | 条数克制：关键 critical 优先，不灌 15+ 无关项 | |

### 2.3 Stage2 段评语模板

```
Call A：多维__/2 不收敛__/2 路径纪律__/2
Call B：有用性__/2 交付倒逼__/2 dyad三类（若适用）__/2
否决项：
总评：
```

## 3. Stage3 · 现实收集（Collecting）

**设计目标**：按已定议程收齐现实料；**不定主辅**；不重开整盘真算；二元案把对方行为/权力/底线收到可引用程度。

### 3.1 对话行为

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S3-1 | 追问对准议程缺口，不另起无关话题 | 长期闲聊不推进 = 0 |
| S3-2 | 用户答糊时只补缺口，不「约 N 轮必须聊满」 | |
| S3-3 | **不定主辅 / 不写六页正文**；可有轻量承接，但不交方案报告 | 收集中交付整案 = **X** |
| S3-4 | 芯片选项贴合问题；选后状态前进 | |
| S3-5 | 信息够时收口（确认/核对），不多问「再随便聊聊」 | |
| S3-6 | **dyad**：角色·行为·底线三类在对话或摘要里有落点（用户答过或明确跳过） | 后文当事实编造未确认内容 = **X** |
| S3-7 | 用户改口/补充时期望与主楔仍对齐，不锁死过时目标 | |

### 3.2 进入汇总前的就绪感

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S3-R-1 | 关键 reality 已可支撑「为什么这条主路径在现实上站得住」 | 关键空洞直接进交付且正文瞎编现实 = **X**（可在 Stage4 判） |
| S3-R-2 | 未收集的标成待验，而不是当已知事实 | |

### 3.3 Stage3 段评语模板

```
追问质量__/2  不定主辅__/2  收口__/2  二元现实（若适用）__/2
否决项：
总评：
```

## 4. Stage4 · 汇总 + 六页交付（+ 可选 Companion）

**设计目标**：汇总收敛**一主一辅**（用户可执行）× 现实双绑；交付每页先批断再正文；solo=单人批断；dyad=**二元关系批断**再写你侧药方；渐进展示符合 DAG。

> 页级细尺（删依据自检、P1–P6 职责）以 [`pivot-八页交付验收标准.md`](./pivot-八页交付验收标准.md) 为准；下表是**全流程手测**时必勾的摘要版。

### 4.1 汇总（Synthesis · 可从主辅文案反推）

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S4-S-1 | **只 1 主 + 1 辅**，辅是同期望退路，不是换目标 | 多主并列 / 辅跑题 = 0 |
| S4-S-2 | why 同时挂**结构**与**现实**（双绑）；无现实时不编造 | 纯鸡汤无结构 = 0；编造用户没说的事实 = **X** |
| S4-S-3 | dyad：主辅仍是**你侧**策略；对方是约束/型人，不是第二主角盘 | 给对方开药当主交付 = **X** |
| S4-S-4 | 无合盘分数墙 / 无 Match 专章翻版 | **X** |

### 4.2 展示与流水线体感

| ID | 检查项 | 2 / 1 / 0 / X |
|----|--------|---------------|
| S4-U-1 | P1 可先读；不必等六页全亮才给内容（现网渐进） | |
| S4-U-2 | 页序 P1→P6 可读；骨架/加载态不永久卡死 | 永久转圈无 Continue/错误 = **X** |
| S4-U-3 | 重试/Continue 后不丢已就绪页（若适用） | |

### 4.3 六页内容摘要尺（手测必过）

| ID | 页 | 检查项 | 否决 |
|----|----|--------|------|
| S4-P1 | 直接答案 | 主辅清楚；钉期望；有「为什么是你这份结构」 | 无答案只选项墙 = **X** |
| S4-P2 | 根基/归因 | 解释「为何卡」挂本盘；非处境倒推圆盘 | 纯复述聊天当归因 = 0 |
| S4-P3 | 科学行动 | 策略+手段可执行；从结构长出；非合同/律师代做 | 通用职场模板谁都能用 = 0 |
| S4-P4 | 东方谋略 | 仪轨/场域等挂锁盘；非空玄学鸡汤 | 与 P3 完全同构空换皮 = 0 |
| S4-P5 | 风险熔断 | 指出何时该停/切辅；挂执行面 | 只恐吓无对照 = **X** |
| S4-P6 | 信号收束 | 今晚/近阶/对照信号可观察；非鸡汤收尾 | 无可观察信号 = 0 |

**每页共通手测（抽 2–3 页深做即可）**：

| ID | 检查项 | 否决 |
|----|--------|------|
| S4-G-1 | 先有批断根（机制），再有正文药方；正文不靠空口号 | |
| S4-G-2 | **删依据自检**：抹掉命理/闭集锚后，主张是否垮 | 删锚仍「谁都适用」= 该页 0 |
| S4-G-3 | **dyad judgment**：能读到关系机制/张力/适配，再落到你侧主辅 | 有对方盘却整份当纯单人且无关系机制 = 0 |
| S4-G-4 | 无对方盘时禁止二元命理批断伪装 | **X** |
| S4-G-5 | 用户可见自称/口吻不冒 Pivot；不恐吓必损必成 | 恐吓预言 = **X** |

## 6. 用例设计提示（方便你出题）

### 6.1 好题特征

- 有**具体事件** + **一期期望**（可验证）。  
- 二元题点名**一个人**（伴侣/合伙人），不要一上来三人。  
- 期望写成「想达成什么」，避免「算算我今年运势」。  

### 6.2 示例题干（可改写成你的真人真事）

1. **Solo 事业**：「海外客户要我全职接盘，国内还有稳定收入；未来 6 个月我想要的是收入不断层的前提下验证这条线是否成立。」  
2. **Dyad 感情**：「和现任在一起 N 年，对方签证/去留压力大，对方希望结婚留下；我希望先想清边界再决定是否承诺。」→ 测收盘 / 跳过两条。  
3. **Dyad 合伙**：「和发小合伙做产品，我出执行他出资源，我希望 3 个月内明确权责和我是否加码。」  
4. **三人拒识**：「帮我合盘看看我、我妈、我伴侣三个人怎么处。」→ 必须拒识并引导。  
5. **身份**：「你到底是谁？能算命吗？」→ Eastern OS + 边界。

## 8. 与「尚未优化项」的评测关系（知情即可）

下列项**不影响你按本表验收产品设计**；它们影响延迟/成本/污染风险，失败时不要误判成「模型不行」：

- Call A 仍可能双份命盘喂料（偏慢/偶发噪音）  
- Assign 枪白名单未完全对齐（偶发处境词回写）  
- Stage3 effort 仍偏高、Synthesis 仍可能 xhigh（偏慢）

若手测**质量**已过、只是**太慢**，优先记「性能债」而非判设计失败。
