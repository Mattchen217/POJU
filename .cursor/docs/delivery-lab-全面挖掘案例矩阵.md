# Delivery Lab · 全面挖掘案例矩阵（设盘手册）

> **用途**：按「触发维」设计多盘 Lab，把事实层（F）与呈现层（P）债挖全，而不是赌单一好运盘。  
> **读者**：你（设用户画像 + 议题文案）+ 验收时对照活文档签字。  
> **相关**：活文档 [`delivery-lab-分步验收标准.md`](./delivery-lab-分步验收标准.md) · Canonical [`pivot-八页交付验收标准.md`](./pivot-八页交付验收标准.md) · 规则 11/12  
> **维护**：新穿闸 → 在对应「触发维」加一行「已由哪盘触发」；修根后标回归脚本，**勿删维**。

---

## 0. 先答你的三句

1. **要不要多案例？** 要。一条链路上的 F 是「路径敏感」的：事业盘验不到亲密施事，亲密盘验不到创业伙伴句模，岁运薄盘验不到菜单挤峰。  
2. **是不是所有洞都触发完才算合格产品？**  
   - **产品可卖的底线** = 活文档 **F 项**在「最小覆盖集」上全部可回归绿 + 新盘不再假绿。  
   - **持续合格** = 矩阵里每条触发维至少被 **1 盘真触发并签字**（或 fixture 等价触发）；P 项可登记后修，不挡发版，但要进排队。  
3. **本文怎么用**：下面每张「案例卡」= 一种用户 + 一种困境写法；你按卡填真实/半真实盘与收集答案 → 跑 Lab → 只验该卡列出的触发维（其它维空过不算签字）。

**闸门绿 ≠ 该维已验。** 只有「本卡目标维出现过风险句 / 锁错 / 假绿」再被修或确认干净，才算挖到。

## 1. 合格定义（和「挖全」的关系）

| 层级 | 含义 | 何时算过 |
|------|------|----------|
| **L0 结构可跑** | 30 步能跑完、无设计性 504 | 任意一盘 |
| **L1 最小 F 覆盖** | 下表「最小集」每维至少 1 盘触发并 F 签字或回归绿 | **发版前必达** |
| **L2 矩阵全覆盖** | 本文全部触发维都有签字/fixture | 质量里程碑；可分季度补 |
| **L3 换盘抽检** | 每修一批根，抽 1 盘未在矩阵里的新议题 | 防过拟合 fixture |

不要追求「一个超级用户一次触发全部」——议题互相打架时模型会糊成一团，**挖洞效率反而差**。

## 4. 案例卡（按此设用户与困境）

写法约定：

- **用户壳**：年龄段 / 关系状态 / 职业阶段（不必真名）。  
- **命盘注意**：尽量选**真算后**该维有料的盘（例如亲密卡要有夫妻宫/关系岁运信号；合伙卡要有合局/官杀）。Lab 可换 fingerprint，议题文案按下表写。  
- **收集答案**：故意设计「可错配」与「干净」两种；挖 A9 时用错配列。  
- **成功标准**：见卡末「本卡算挖到」。

---

### C-事业分叉（最小集 #1）

**目标维**：A4–A8、A10、B3、B5、P3 辅轨同模  

**用户壳**  
- 30–45 岁，大厂/传统行业中层，单身或伴侣不进主矛盾。  
- 有一笔「看起来能撑一段时间」的存款，但怕断现金流。

**困境文案（议题）**  
> 我做了 N 年中层，晋升卡死、内耗大，想转行/接外部项目/做独立顾问，又怕丢稳定收入。家里人有意见但**不是本案主线**——本案只问：留 vs 走、怎么过渡，不要替我做商业计划书。

**收集项建议（干净版）**  
- 现状 / 期望 / 分叉 / 安全垫月数 / 专业可变现证据 —— **label 与 answer 对齐**。  

**本卡算挖到**  
- [ ] prealloc=`thesis_menu`，无影子词  
- [ ] 无裸「格局/六合」主承重；裸五行若出现已 demote 或记 P  
- [ ] P3 辅轨三角若同模 → 登记 B3，不挡则 unlock  
- [ ] write 无 shallow  

**对照盘**：2026-09 乙木·career（制造业→新能源）类。

---

### C-亲密阻力（最小集 #2）

**目标维**：A1、A3、A9、B1、B2、fill 用户层施事  

**用户壳**  
- 有稳定伴侣或家人强意见；议题**明确**含关系阻力。  
- 可叠加事业焦虑，但**至少一张 why 卡**必须落到关系表象。

**困境文案**  
> 我想动职场/学业上的大变化，但男友/伴侣/家人强烈反对，觉得我该稳定/结婚生子。我每天焦虑：继续耗着不行，动了又怕关系崩。请诊的是**我侧结构与节奏**，不要合盘，不要替对方说话。

**收集项（挖 A9 用 · 错配版）**  
故意做 1–2 条错绑，例如：  
- label=`对方反对的核心原因` → answer=`我的专业其实已有人付费`（答非所问）  
- label=`专业与客户` → answer=`能撑 6–12 个月`  

另备 **干净版** 对照：label/answer 对齐后再跑一盘，确认 #3 修复后不再穿。

**本卡算挖到**  
- [ ] assign 解释层无第三方施事；若 claim 曾脏 → 软修后干净  
- [ ] write evidence 无「反对是因为某信号」；若只剩摩擦模全文 → 记 B1（逼近 F）  
- [ ] **fill essence** 无「导致对方反对」——不过则整步 F  
- [ ] 错配 cite 是否进 mark 标题 → 记 A9  

**对照盘**：2026-09-17 乙木·relationship（fp `1d592e5c…`）类。

### C-合伙盘子（最小集 #3）

**目标维**：A2、合伙句模 vs 亲密句模分流  

**状态（2026-09-17）**：亲密盘根修已合（weld 窄化 / claim 禁令剥 / 关系复合单金字）；**本卡待开 Lab**。

**用户壳**  
- 有「旧部 / 创业伙伴 / 发起人」邀约；你是加入方或股权不清。
- 命盘尽量真算后有合局/官杀（可复用乙木盘或另选合局明显的 fp）。

**困境文案（粘贴用）**  
> 前同事拉我进项目，对方是发起人，我更像加入他的盘子；他说希望我全职，我只想兼职试水。问的是我侧话语权与开口节奏，不要写成恋爱关系。我怕开口谈兼职边界时被当成不够投入，也怕全职进去后没有话语权，变成一直配合他节奏。想要的是：结构上我处在什么位置、今晚怎么开口试水、红灯出现时怎么停主切辅——不要替我写合伙协议或邮件话术。

**收集项**  
- 话语权 / 兼职接受度 / 谁发起 / 你怕失去什么 —— 用「伙伴/旧部」字样，**避免**男友/婚姻词。

**Lab 开盘**  
1. `/ops/delivery-lab` → 从本机导入会话（或选手动 JSON）  
2. 议题用上文困境文案；`question_category` 建议 career / partnership  
3. Bootstrap → Thesis → … 按游标；重点盯 foundation/science assign inference **不得**出现「亲密关系议题」套话  

**本卡算挖到**  
- [ ] 软修走 **partnership** 模，不出现「亲密关系议题」套话  
- [ ] 无「他希望我…」当机制主语  
- [ ] science cite 含「合作/关系」时 inference 不被 intimacy weld 盖掉  

---

### C-岁运挤峰（最小集 #4）

**目标维**：A5、A6、A7、A11、A12、P5/P6  

**用户壳**  
- 议题含「最近这段时间特别拧 / 想近阶动作」；盘上岁运关系信号宜多（刑冲合害叠层）。

**困境文案**  
> 大方向我已经有主辅倾向了，但近阶段一直反复横跳，想要的是**今晚能做的一件事 + 近 7 日可验证小步**，不要给我排一个月日程表，不要替我做决定的合同动作。

**收集 / 合成注意**  
- breakthrough `rhythm_frame` 若被写成「第1-10天…」→ 正好挖 A12。  
- 菜单词多时盯 prealloc 是否把长关系句留给 foundation/science，把裸五行甩给 risk。

**本卡算挖到**  
- [ ] 无相刑/相害抄错  
- [ ] P6 day7 无月表腔（或软修压回近 7 日）  
- [ ] 跨页 primary reuse ≤ cap；fill 不因误闸空转  
- [ ] 无四周任务表 / 替执行  

---

### C-资源/表达薄（最小集 #5）

**目标维**：藏干财星、食伤薄、末卡承重、expression 菜单被先占  

**用户壳**  
- 问「值不值得为兴趣/作品投入」或「收入结构太隐性」；盘上财星/食伤多为藏干。

**困境文案**  
> 我外面看起来稳定，但可变现的作品/客户很少；想知道结构上资源是「藏着」还是「没有」，以及表达出口怎么用，不要鸡汤鼓励。

**本卡算挖到**  
- [ ] thesis `resource_pattern` 兼藏正财/偏财不漏  
- [ ] 末卡删依据后仍能指向主辅，而非纯心理安慰

## 5. 扩展案例卡（L2 · 按需加）

| 案例卡 | 多挖什么 |
|--------|----------|
| **C-健康边界（非医疗）** | 精力/睡眠极限；禁医疗脏腑结论；dashboard 身体维 |
| **C-双轨已定只要节奏** | P1 直答贴题；禁重新发明第三套药方 |
| **C-海外/跨文化工作** | 英文 UI 下中文命理不泄漏到用户层；术语只进依据层 |
| **C-收集极残** | agenda 很短；sparse_mode；禁 inventory 回灌 |
| **C-多第三方** | 家人 + 伴侣 + 合伙人同时出现；施事闸不漏、句模不串味 |
| **C-钱与关系绑死** | 「不结婚就不支持创业」类；表面钱、机制仍须落你侧开口 |

每加一卡：复制 §4 格式，写清目标维 + 本卡算挖到。

## 6. 单盘操作清单（你设盘时勾）

开 Lab 前：

1. [ ] 选定 **案例卡 ID**（本盘主攻哪 2–4 个触发维）  
2. [ ] fingerprint / as_of 固定；议题字数足够（建议 ≥300 字中文处境）  
3. [ ] 收集项：挖 A9 用错配，其它维用干净配对  
4. [ ] 写下「本盘不验哪些维」（避免空过当签字）

每步：

5. [ ] 闸门结果 + **目标维**肉眼（对照活文档 F）  
6. [ ] 穿闸句 **原文**记入活文档「已登记问题」（只增不扔）  
7. [ ] F → 修根 + 回归脚本；P → 登记方案 A 排队  
8. [ ] **禁止**用「换盘再碰运气」代替修根（规则 11）

盘结束：

9. [ ] assemble 通读：删依据自检 + 无替执行  
10. [ ] 更新本文件「对照盘 / 已由哪盘触发」一行

## 8. 一句话

**全面测 = 用不同用户×困境把触发维打勾，不是用一个完美故事证明永远正确。**  
最小集 5 类把 F 路径盖住；已跑过的类不必为凑数整盘重开，未跑的类才是下一盘。
