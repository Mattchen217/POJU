# Pivot · 从输入八字到交付报告完成（白话全链路）

> **用途**：用大白话说明**最优完整路径**——谁为谁服务、什么进交付、什么不进。  
> **口径**：目标因果链（强因果、少分叉）。与现网若有出入，以本文件为改造方向；实现细节以仓库规范与代码为准。  
> **不是**：代码文件清单、提示词原文。

最后更新：2026-09-09（定稿：二算/题向收敛均为独立前置步；第2段仅轻量分诊）

---

## 0. 一句话总览

用户留下出生信息 → **第一次本地算**（本命，只算一次）→ 右侧八字/能量列表 →  
**第1段**弄清问题与期望 →  
**第2段**做一次贴题分析，**只为排出准确议程** →  
**第3段**按议程收齐现实细节 →  
**第4段才正式交付**：带着「本命 + 题/期望 + 议程细节」做**第二次本地算** → **命盘总纲**按维做详细真批断 → 在总纲 + 现实上收敛主辅与行动 → 各页按固定核心方向、随总纲动态长出正文与依据。

整条链的铁律：

| 东西 | 角色 |
|------|------|
| 第一次本地算 | 不变的本命事实源 |
| 第1段 | 弄清「问什么、想要什么」 |
| 第2段 | **只服务第3段**——没有这次分析，议程会空穴来风 |
| 第3段 | 弄清「这件事在现实里卡在哪」 |
| 第4段 | **交付才开始**；吃本命 + 第1/3段用户料；**不吃**第2段分析全文 |
| 总纲 | 按维组织的真算真推理（传统批断深度）；页随之动态调整 |
| 页 | **只固定核心方向**，不固定段落墙 |

全程表达：盘是真算、本地、确定性；用户正文行为/精力白话；命理真词进依据折叠层；不替用户执行。

---

## 1. 进门：留下八字信息

1. 用户进入 Eastern OS / Pivot 工作台。  
2. 填写或选择档案：出生年月日时、地点（尽量真太阳时）、性别等。  
3. 档案存**本机**（加密）；对话正文不当服务器聊天库存。  
4. 确认后进入准备态，后台启动**第一次本地计算**。

此时还没有交付报告，也没有旧版「个人能量长文」。

---

## 2. 第一次本地计算：只算「不会随题变」的东西

产出落盘，全站共用，即**本命底座（structured）**。

大致包括：四柱干支、日主、藏干、十神；身强弱；用神/喜忌；大运与当前步；闭集神煞实例；以及给机器用的核心判断浓缩（不是给用户看的长散文）。

**不做：**

- 不写旧个人能量长报告  
- 不按工作题/感情题各算一套本命  

**给谁用：**

- 右栏**八字/能量列表**：真算 + 本地模板填格，**零模型写矩阵**  
- 对话与交付共用同一份本命事实源  

出生关键信息改了才清掉重算；平时不重算本命。

---

## 3. 列表亮起，对话可以开始

右栏出现个人能量/八字列表；中心进入聊天。  
标志：**本命已就绪**。用户主路径是「列表 + 对话」，不是旧底座长文。

---

## 4. 第 1 段 · 开局：弄清问题与期望

**目标：** 弄清「卡在哪」「想往哪去」，并确认理解。  
**不定**最终破局方案，**不定**一主一辅。

大致发生：

1. 白话聊，收**具体困境 + 期望方向**。  
2. 盘已在，可轻锚结构；不灌八页交付、不灌打标教学。  
3. 够清楚 → 理解摘要，请用户确认或补充。  
4. 确认后锁定问题表述（及期望）。

**本段交给后面的料：** 锁定的问题 + 期望。  
通过确认门 → 第 2 段。

---

## 5. 第 2 段 · 贴题分析：只为第 3 段排出议程

**为什么需要这一段：**  
第 3 段的议程不能空穴来风。必须先在本命 + 已确认的题/期望上做一次**贴题分析**，才知道「接下来该问哪几条现实线」才贴题、有用。

**本段产出：**

1. 一份贴题分析（处境怎么拆、哪些线值得查清）——**只服务排议程**。  
2. **调查议程**（若干条要问清的现实线）。

用户侧常见：短复盘 + 定调 + 引出「我接下来要问你几件事」。不是甩整份 JSON，更不是八页交付预告。

### 分诊 vs 确诊（防第三套指引）

第 2 段引用本命时，只做**轻量提示级**判断（分诊）：够用来决定「该问哪几条现实线」即可。  
**禁止**在本段生成结构化的、可被下游依据引用的判断核（简化版总纲）。

| | 第 2 段（分诊） | 第 4 段总纲 + 题向收敛（确诊） |
|--|----------------|--------------------------------|
| 深度 | 粗略、够排议程 | 按维可举证、删依据应垮 |
| 产出 | 议程问线 | 批断 + 主辅方案 |
| 下游能否当依据 | ❌ 不能 | ✅ 可以 |

刻意分开做，不是浪费：图省事把第 2 段做成「迷你总纲」，会再长出第三套交付指引。

### 因果边界（重要）

| ✅ 第 2 段做什么 | ❌ 第 2 段不做什么 |
|----------------|-------------------|
| 为第 3 段生成贴题议程 | **不**当交付终态脊柱 |
| 让收集问得准 | **不**把分析全文灌进 P1–P6 feed / 派工 |
| 可有多维发散，方便排问线 | **不**在这里定死最终一主一辅 |
| 本命轻量提示级引用 | **不**产出可被依据层引用的结构化判断 |

一句话：**第 2 段本质只为第 3 段服务；用完即弃。**  
没有这次分析 → 议程不准 → 收集空 → 交付悬。  
有了这次分析 → 只把**议程**往下传；分析正文**不进**第 4 段交付输入。

---

## 6. 第 3 段 · 收集：按议程收齐现实细节

**目标：** 按第 2 段排出的议程，把约束、资源、关系、已尝试的事等**问清楚**。

规则：

- **仍不定**最终一主一辅（收敛留在第 4 段）。  
- 每条问到满意 → covered，记下用户原话。  
- covered 问答 = 交付要用的**现实证据**。

收集够了 → 用户确认可以出报告 → **第 4 段正式开始**。

**本段交给交付的料：** 议程细节（covered_agenda）。

---

## 7. 第 4 段开场：交付正式开始——手里该有什么

到这里，对话三阶段结束。交付编排**只应拿到**：

| 材料 | 来源 | 进交付？ |
|------|------|----------|
| 本命 structured | 第一次本地算 | ✅ |
| 用户问题 + 期望 | 第 1 段 | ✅ |
| 议程细节（covered） | 第 3 段 | ✅ |
| 第 2 段贴题分析全文 | 第 2 段 | ❌ 不进（已完成「排出议程」的历史使命） |

然后按下面顺序走完交付。

---

## 8. 第二次本地计算：独立前置步（题时补充包）

**时机（已敲死）：** 第 4 段内、**总纲之前的独立步骤**。  
不是塞进总纲函数内部的副作用；Delivery Lab 必须能**单独点跑 / 单独重跑**本步，以便分清「二算错了」还是「总纲生成错了」。

**输入：** 本命 structured + 问题 + 期望 + 题型 + 议程里需要的锚 + `as_of` 日期。  
（**不**喂第 2 段分析全文。）

**性质：** 确定性代码补充——**不是**再算一套本命，**不是**模型深度测算，**不是**旧能量长文。  
按题类做的是**筛选 / 加权切片**；规则查表进引擎；流派分歧进带版本号的启发式（可测、可复现）；传统命理无确定性区分处如实写「未见结构性区分依据」，转交第 3 段现实细节，不硬凑。

**岁运层（v1 敲死）：** 只算 **大运 + 流年 + 流月**。  
Atmos/`relation-engine` 另有**流日**能力，**不进** TopicCalcSupplement（避免日粒度噪声进总纲；需要时另开版本契约）。  
读摘要时：「流月引动·**日支**」里的「日支」= 本命日柱地支，**不是**流日。

**产出：** `TopicCalcSupplement`（题时补充包）→ 交给下一步总纲。  
含：岁运时钟、叠层关系、用神**元素**扶抑表、题类菜单、**中性** `rhythm_signals`。  
**不含：** `near_term_bias` / 宜冲宜守打包裁决（冲守只归总纲 `cycle_rhythm`）。  
字段与缺口：`.cursor/docs/pivot-TopicCalcSupplement-字段草案与缺口表.md`。  
实现：`lib/calculations/topic-calc-supplement/`（尚未接总纲 feed / 交付派工）。

能量列表仍用不变本命；交付用药对准**这一题**。

## 9. 命盘总纲：按维详细批断（只管「盘上是什么」）

总纲吃：

- 第一次本地算（本命）  
- 第二次本地算产出（题时补充包）  
- 议题/期望（**只调各维详略**，**不改**真算判断内容）  
- 议程细节（供后步题向收敛与落地校准；不污染「盘上是什么」）

总纲产出：**按维度组织的详细真算真推理**——专业命理批断深度，例如（**示例，非模板套句**——禁止当内容模板凑叙事）：

> 观尔命盘：丁火日主，生于午月，建禄当权，火势炎上。干透丙火帮身，地支寅午半合火局，局中木火偏旺，日主得令得地，身强之象。月干透出癸水七杀，然无庚辛发源，地支无根，显虚浮之象。局中燥气太重，急需「金水相涵」以成润局之功。

原则：

- 按维写透；维数与厚度可随题动态调整（无关维可薄）。  
- **不**固定死报告每一段散文模板。  
- 下游每一页的依据必须能挂上总纲；删依据应垮——才叫扎根。  
- 用户可见正文仍走白话契约；批断里的真词主要服务依据层 / 专业核，不整段裸扔进主文。  
- **同一份命盘**，不同议题下真算判断内容必须一致；议题只影响详略（合规红线）。

**总纲只管：** 这盘结构性是什么、为什么。  
**总纲不冒充：** 「这一题最终主走哪条」——那是下一步题向收敛。

**备忘（可后做，今天不拍板）：** 若「议题不污染判断」已能验证，可将总纲**判断内容**在第一次本地算后缓存；每次交付只重跑详略分配。大运换步 / 流年边界需失效策略。先跑通链路再考虑。

---

## 10. 题向收敛：独立步骤（只管「这题该怎么走」）

**时机（已敲死）：** 总纲完成之后、逐页生成之前的**独立步骤**。  
**不**与首轮派工紧耦合；Lab 必须能单独点跑 / 单独验收「主辅与行动骨架」，避免「这题该走哪条」埋进派工黑盒。

**输入：**

- 总纲批断（盘为什么这么说——必须先有总纲，否则会凭用户自述空转）  
- 第 1 段问题/期望  
- 第 3 段议程细节  
- 题时补充包中的**事实切片**（cycles / relations / 中性 `rhythm_signals` / 元素扶抑表）——仅作举证材料  

**可读边界（方案 B · 已敲死）：**

- **冲守节奏**的最终解释权 = 总纲 `cycle_rhythm` **唯一**。  
- 题向收敛**不得**把二算信号当成第二套「宜冲/宜守」结论，也不得与总纲冲守结论并列仲裁。  
- 二算包内**不存在** `near_term_bias` / push-hold-retreat 字段。

**产出：** 主路径 / 辅路径、行动计划摘要等——交付页要用的方案方向。

这里才定一主一辅。  
**不再**回灌第 2 段分析当终态。

---

## 11. 逐页生成：固定核心方向，内容随总纲动态长

用户付钱带走的是交付书。

### 11.1 页的核心方向（固定职责，不固定字数墙）

| 页 | 核心方向（白话） |
|----|------------------|
| 直答 | 正面回答所问；主路径一句话说清 |
| 根基 / 表象 | 为什么是他；表象如何对到结构成立 |
| 科学行动 | 可执行的行为/精力策略（从总纲+收敛长出） |
| 东方行动 | 护城河：时机 / 极性 / 格局手段等（从真算长出） |
| 风险熔断 | 别踩坑、怎么自检 |
| 收束信号 | 近阶信号与收尾；不替做执行 |

每页根据**自己挂到的总纲批断 + 题向收敛 + 现实细节**，完成该页正文与依据。  
claim 多少、段落厚薄：**随总纲实际内容动态定**，不强行凑历史模板段数。

### 11.2 单页大致工序

Assign（要证什么、挂哪维）→ Write（专业依据）→ 质检 → Fill（用户可读结构）→ Mark/润色（打标、双层、纯度）。

可用 Delivery Lab 逐步点跑验收。

### 11.3 质量尺子

- 答案清不清楚  
- 药方是否从**他的盘与总纲**长出（删依据应不成立）  
- 不替执行、不万能鸡汤  
- 闸门只验收；不够改提示/软修，**禁止**无意义重试碰运气  

### 11.4 拼书

各页通过后组装预览 / 正式书架。正文白话；依据可折叠。Lab 半成品不当付费正式书。

## 12. 交付之后

可读完整报告；可进入跟踪/短聊（仍锚同一本命，不重开整本八页）。  
本机保留盘与会话；服务器不存用户对话正文。

## 13. 整条链路一张表（最优因果）

```text
输入八字/出生
    ↓
【第一次本地算】本命 structured（不变）
    ↓
八字 / 能量列表（真算 + 模板）
    ↓
第1段 开局：问题 + 期望 → 确认
    ↓
第2段 贴题分析（轻量分诊）→ 排出议程
        （分析全文到此为止；不进交付；不做迷你总纲）
    ↓
第3段 收集：按议程收细节 → covered
    ↓
用户确认出报告  ★ 交付从这里才开始
    ↓
第4段 输入 = 本命 + 问题/期望 + 议程细节
    ↓
【独立】第二次本地算 → TopicCalcSupplement
    ↓
【独立】命盘总纲：按维详细真批断（议题只调详略）
    ↓
【独立】题向收敛：主辅 + 行动骨架
    ↓
逐页：固定核心方向 · 随总纲动态长正文与依据
    ↓
拼书验收 → 交付完成
```

### 谁为谁服务（一眼看清）

```text
本命 ──────────────┬──► 列表
                   ├──► 第2段轻量分诊（仅排议程）
                   └──► 二算 / 总纲

第1段 题+期望 ─────┬──► 第2段（帮分析贴题）
                   └──► 第4段（交付输入 + 题向收敛）

第2段 ─────────────► 只► 第3段议程
                      ✖ 不► 第4段 feed / 依据

第3段 细节 ─────────► 第4段（交付输入 + 题向收敛）

总纲（盘）+ 题向收敛（题）──► 各页正文与依据
```

**三权分立（已敲死）：** 总纲管盘 · 题向收敛管题 · 第2段只管议程。三者不抢「交付往哪走」的最终裁决。

## 14. 和「旧个人能量长文」的关系

- 已取消作为用户主路径展示。  
- 不进交付提示词。  
- 旧档案里的 `display_text` 是历史残骸；真链路用 **structured + 题时补充 + 第1/3段用户料 + 总纲**，**不用**第2段分析全文当交付原料。

---

## 15. 与现网的关系（避免误会）

现网仍可能把第2段 `breakthrough_core` 灌进交付派工/feed，并另有对话期「综合」步；总纲 calc feed 仍可能把流年标成 absent。  
**本文件是目标最优因果：** 第2段退出交付；二算 / 总纲 / 题向收敛均为**可单独验收的独立步**；方案方向只在题向收敛定。  
改造按本表收敛，避免三套指引并存。

---

## 16. 自检：这条链路干净吗

1. 本命是否只算一次？列表是否只吃本命？  
2. 第2段是否**只**为排出议程，且仅为轻量分诊（无迷你总纲）？分析全文是否**明确不进**交付？  
3. 第3段议程是否明显依赖第2段（不是空问）？  
4. 第4段输入是否只有：本命 + 题/期望 + 议程细节？  
5. 二算是否为总纲前的**独立步骤**（Lab 可单独点跑）？  
6. 总纲是否按维写出可删垮的真批断？议题是否只调详略？  
7. 题向收敛是否为总纲后、逐页前的**独立步骤**（不与派工耦合）？主辅是否只在此定死？  
8. 各页是否只钉核心方向、段落随总纲动态、正文白话 / 依据挂总纲？  
9. 隐私：本机加密存档、服务器不存对话正文？

任一条否，优先修**因果与契约**，不要靠多烧模型碰运气。
