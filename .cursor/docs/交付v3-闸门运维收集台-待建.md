# 交付 v3 · 闸门运维收集台（待建）

> **状态**：已立案 · **开工条件 = Lab 页（v3）测稳后**（类别尺进冻结清单并升闸到可拦可记）。  
> **对齐**：`交付v3-Lab人审失败类别-待冻结闸门清单.md` · `交付报告-三步链路-架构.md` · Never Stored（`00-core`）。

## 1. 为何要建

生产闸门 = 验收尺（只验不改）。不过 → **显式 fail**，禁止质量空转重试抽奖。  
运维靠：失败可观测 → 按**类别**聚类 → 达阈值改 prompt/菜单发版。  
Lab 测好后必须有一套收集能力，否则失败信号无处落地。

## 2. 产品形态（薄后台，信息不少）

- **不做**：复杂 BI 仪表盘、完整交付报告云端存档、自动重抽到过闸。  
- **要做**：结构化失败日志 + 按周/按阈值简单聚合表（可先内部工具页或导出 CSV）。

## 3. 最低完整字段（够针对性修 · 遵守 Never Stored）

| 字段 | 必填 | 说明 |
|------|------|------|
| `failed_rule` | ✓ | 机闸规则 ID（如 `gate_judgment_situational_path_words`） |
| `page` | ✓ | `direct_answer` / `foundation` / … |
| `step` | ✓ | `content.judgment` / `content.body` / `gate` |
| `pipeline` | ✓ | `v3_three_step` |
| `prompt_fingerprint` 或 git SHA | ✓ | 对上发版，避免修错版本 |
| `model` + `generation_id` | ✓ | 供应侧 vs 生成侧 |
| `unit.path` | 有则填 | 哪条主张翻车 |
| `trigger_excerpt` | ✓ | **仅**命中字段短截（claim/evidence 等，百字级），非全文 |
| `chart_fingerprint` | ✓ | 哈希，非命盘原文 |
| `topic_bucket` | ✓ | 粗类枚举（合伙/事业/情感…），非问题原文 |
| `locale` + `timestamp` | ✓ | 聚合与节奏 |

**禁止长期入库**：完整用户问题/期望、处境材料全文、完整 Fact-pack、整页正文、可识别对话。  
（本地 Lab / 设备侧调试可看全量；生产运维库只留上表。）

## 4. 运维节奏（非 7×24 值守）

1. 失败写入收集台。  
2. **按周或按 `failed_rule` 计数阈值**扫：同类达阈值 → 开修。  
3. 主修 = prompt / 菜单 / 喂料（类别）；改尺仅误杀/漏放整类，且同步提示词。  
4. 发版后观察该 `failed_rule` 是否下降。  
5. **禁止**：每个 fail 即时热修；禁止自动连抽到过闸。

## 5. 与 Lab 冻结清单的关系

- Lab：发现类别 → 写清单 → 升闸。  
- 生产收集台：用同一套 `failed_rule` ID 记账。  
- 新类别若生产冒出且清单没有 → 追加清单 → duty → 升闸（提前升闸规则见冻结清单 §0）。
