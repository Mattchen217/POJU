# 提示词按阶段隔离 · 防再污染备忘

> **每次改 POJU 提示词先看本页。**  
> 五份「提示词分干净」是治标（清已污染）；本条是治本（防再污染）。

---

## 铁律

**交付专用规则（打标 / 双层 / 金字纪律 / 语法润色）绝不进全阶段恒在的身份层 / 控制面。**

要加，只能：

1. **phase 门控**（例：`PHASES_NEEDING_TERM_MARKING`、`phase === "delivered"`、`PHASES_SLIM_CHART_DATAPLANE`），或  
2. **该阶段自己的 taskBlock / Call 专属 TASK**（例：`DEEP_RECKONING_REPORT_TASK`、opening rules、八页 `final-delivery` 自带块）。

**改提示词 = 改对应阶段。全局改 ≠ 往共用层加一段「方便」。**

不立这条，下次有人往共用层加一段，清理成果会被打回原形。

---

## 病根（短记）

| 污染源 | 症状 |
|--------|------|
| 身份层教「每个命理词打标」 | 全阶段恒在；对话无闭集表、下游不解析 ⟦t:⟧ |
| 控制面无差别拼交付向块 | opening/collecting 吃金字/打标/润色 |
| Call A 自建 system 塞双层+打标 | 与「裸词真算、无打标」总纲正面打架 |
| chat termPlane 未按 phase 门控 | 非交付阶段被教一整套打标 |

对话阶段软译/合规呈现走后端 **autoMark**；**只有八页交付**（及明确需要的 `delivered` 门控块）才做完整打标体系。

## 已落地门控（对照，勿回退）

| 机制 | 位置 | 作用 |
|------|------|------|
| `PHASES_NEEDING_TERM_MARKING` | `oriental-prompt-context-v6.ts` | chat 为空集；打标只在八页 `final-delivery` |
| Call A 无双层/打标/8页蓝图 | `breakthrough-core.ts` | 与真算总纲一致 |
| 身份层不教打标 | `POJU_IDENTITY_V6` | 对话不打标、交 autoMark |
| opening/确认门/delivered/tracking 数据精简 | `PHASES_SLIM_CHART_DATAPLANE` | collecting 仍全量 |
| 控制面无交付向块 | `buildPojuUserSideControlPlane` | 金字/选词/润色不进 chat |
| collecting 不定主辅 | `collecting-phase-v6.ts` | 口径对齐五段：先收集后汇总 |
| delivered 短聊瘦契约 | `delivery-phase-v6.ts` | 不塞 DEEP_METHOD 全文 |
| `POJU_OUTPUT_FORMAT` 第2条 | `poju-base.ts` | 已拆成「对话不打标」 |

八页交付打标+双层：只在 `final-delivery`（及交付自有拼装），**不**依赖聊天共用控制面。

## 改提示词自检清单

- [ ] 这段规则属于哪个阶段？文件/门控是否只影响该阶段？
- [ ] 是否试图写进 `POJU_IDENTITY*`、无门控的 `buildPojuUserSideControlPlane`、或「全 Call 共用」拼装？
- [ ] 交付向块是否已在「交付向块清单」且有门控/专属层？
- [ ] Call A / Call B / synthesis / opening / collecting / 确认门 / 交付：各自任务是否仍独立、无互相教对方的规矩？
- [ ] 冒烟：非交付 system/控制面无 ⟦t:⟧ 教学、无双层块；交付层打标仍在。
