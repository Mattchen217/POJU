# POJU 交付报告改版设计(命脉 · 从用户价值出发)

> **定位(用户定的)**:交付报告是产品命脉,前面流程再好、交付不达标全盘皆输。不做补丁式修复,从"用户花钱该带走什么"重新审视,该重构就重构。
>
> **方法**:①先定"用户该带走什么"的尺子 → ②拿尺子量现在的全8页(代码实证体检)→ ③出改版方向。不拍脑袋、不推倒重来(结构是好的),只补命脉、去错位。

---

## 一、尺子:用户花钱,该带走什么(按重要性)

一个带着真实困境(接不接海外/去不去创业/离不离婚)、花了钱的用户,该带走:

1. **一个清晰的答案**:"以你的情况,我建议走这条,为什么"——不是几条平列选项让他自己挑(他就是挑不动才来的)。
2. **只属于他的理由(护城河)**:这个理由**扎在他独有的命理结构上**——朋友/顾问/GPT 都能给建议,但"基于你的能量结构所以这条对你成立"别处没有。
3. **可动手的达成策略与手段**:方向之下,以他的结构**该守什么、该在哪发力、他这类人最容易在哪栽**。要能动手,但**给的是"基于命理的决策策略",不替他做纯专业执行**(不拟合同条款、不写话术脚本)。
4. **自检信号 + 回来的路**:走出去后能对照验证、能回来调。

**一句话尺子**:用户带走的应是"**一份基于我独有命理、告诉我该往哪走·怎么走·怎么验证的决策方案**",不是"一份关于我性格运势的分析报告"。

> **护城河的落点(关键)**:护城河不在 P2"分析你是谁",而在 **P3/P4"怎么办"——当这个'怎么办'是从命理结构推导、只对他成立时**。药方独有,才是护城河;诊断独有没用。

## 三、三个命脉问题(证据确凿)

### 问题1(最致命)· 药方是"事后贴命理标签",不是"从命理生长"
`final-delivery.ts` 第212-213行:WHAT TO DO 三条行动——
- "每条从用户**亲口说过的具体细节**生长"(第212行);
- 末尾补一句 `Profile basis:`(第213行,命盘依据当注脚)。

**生长顺序错了**:先从用户细节造具体行动 → 再事后补一句命理依据。**命理是装饰标签,不是行动来源。** 结果:P3 药方 = 职业建议(谁都能给)+ 命理注脚 → **护城河漏在最该有的地方**(用户花钱买的就是"怎么办",而这个"怎么办"不独有)。
> 对比 P2(诊断):第201行"每子标题至少一处锚定本盘真实结构"——**诊断是从命理生长的,药方不是。诊断扎命理、药方扎用户细节 = 药方和诊断脱节。**

### 问题2 · 颗粒度滑向"替做专业执行"
第228行"WHAT TO DO 三条须**极其具体(时间+地点+人+话+可观察结果)**"→ 产出"周三约老板,这样开口说"这种**执行脚本**,不是"以你的结构,谈判该守什么边界、发力哪、避什么坑"这种**命理决策策略**。
- 丢护城河(执行脚本普通顾问也给);
- 信息不足时被逼编造具体(第163行自己都禁"信息不足别给高风险具体行动"——自相矛盾)。

### 问题3 · 没对齐五阶段重构
交付提示词吃的是"推理脊柱 + 议程证据 + structured节选"(第376-382行),**没吃重构后新增的**:
- **多维真算(6-8维 multi_dimension_reckoning)**——最丰富的分维算料没进交付;
- **汇总段收敛的 primary/backup + action_plan**——交付该基于它展开,但提示词没接。
> 交付用的还是旧算料结构,重构后最值钱的多维+主辅没喂进来。

## 四、改版方向(补命脉 + 去错位,不推倒)

### 方向1 · 药方从命理生长(治问题1·护城河核心)
P3/P4 每条策略的**生长顺序倒过来**:
```
先: 从命理结构(用神/十神/身强弱/大运/主辅方向)推出"以他的结构,这件事该怎么发力/守什么/避什么"
再: 落成可动手的策略(结合用户现实料,但骨架来自命理)
```
- 提示词焊死:**每条行动/策略,先有命理依据(为什么这条对【你】成立、根在你的结构),再生成策略本身**——不是先造行动再补 Profile basis;
- `Profile basis` 从"末尾注脚"升级为"行动的**出发点**"。
> 判据(给原则不给例):**删掉这条策略的命理依据,它还成立吗?——若照样成立(谁都适用),就是没扎命理,重写。** (呼应底座"删掉依据结论还站得住=泛泛而谈"那条自检。)

### 方向2 · 颗粒度校准成"命理决策策略"(治问题2·分寸)
P3 从"极其具体执行脚本"校准到"**基于命理的达成策略与手段**":
- 给:以他的结构**该守什么底线、在哪发力、最易栽在哪、决策时注意什么**(能动手的决策策略);
- 不给:替做纯专业执行(合同条款、话术脚本、背调流程);
- 分寸(给原则):**给"该怎么决策/该守什么"的策略,不给"替你把这件专业活干了"的执行**。前者基于命理·独有,后者是律师/HR的·不基于命理。

### 方向3 · 对齐五阶段算料(治问题3·数据接线)
交付提示词吃进重构后的算料:
- **多维真算(multi_dimension_reckoning)**→ 喂进交付,P2/P3 从多维展开(而非只从脊柱);
- **汇总段 primary/backup + action_plan**→ P1答案/P3策略基于它;
- 确认每页吃哪些上游算料、接对(像议程 serves_page 那样对齐)。

### 方向4 · 逐页验命理扎根(P4/P5/P6)
P4环境/P5节奏/P6避坑,逐页确认"从命理生长"(而非通用模板+命理装饰):
- P4:调频方位/色彩/时段基于用神喜忌(不是通用风水);
- P5:30天节奏基于大运/流年阶段 + 用户可投入时间;
- P6:避坑基于他的忌神/性情盲区(他这类结构特有的坑),不是通用注意事项。

## 五、落地顺序(命脉·逐页验收)

> 依赖前置:**交付链先跑通(那两病合修)→ 能出报告 → 再改交付质量**(改了才验证得了)。

1. **前置**:交付卡死两病修完,报告能端到端出来。
2. **改版1·对齐算料**(方向3):交付吃多维真算+主辅——**先接数据,后改要求**(没数据改要求是空的)。
3. **改版2·药方从命理生长**(方向1,护城河核心):P3/P4 生长顺序倒转 + 依据前置自检。
4. **改版3·颗粒度校准**(方向2):P3 从执行脚本→命理决策策略。
5. **改版4·逐页验命理扎根**(方向4):P4/P5/P6 逐页。
6. 每页改完,拿"三盘对照"验:三个差异大的困境→药方不雷同、每条删掉命理依据就不成立、无替做执行、无通用模板。
