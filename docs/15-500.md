# 15 · 500 错误页

## 页面身份

| 项 | 值 |
|---|---|
| 路由 | 全局错误捕获（Next.js `error.tsx`） |
| 文件位置 | `app/error.tsx` + `app/global-error.tsx` |
| 页面标题 | `Something went wrong — POJU` |
| 目标用户 | 遇到服务器错误 / 前端 runtime 错误的用户 |
| 核心目标 | 温和承认错误，提供恢复路径，记录到 Sentry |
| 优先级 | 必须（Task 1） |
| 所属 Task | Task 1 |

- 自动触发（任何页面出现 unhandled error 时）
- Next.js 会渲染 `error.tsx`


- 样式：Primary 紫色 pill
- 点击行为：调用 Next.js 的 `reset()` 函数（重新渲染组件树）

## 功能与交互

### Error Boundary

使用 Next.js App Router 的 `error.tsx`：

```typescript
'use client';

import { useEffect } from 'react';
import * as Sentry from '@sentry/nextjs';

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    // 记录到 Sentry（过滤掉敏感数据）
    Sentry.captureException(error);
  }, [error]);

  return (
    <div className="error-page">
      {/* UI 内容 */}
      <button onClick={reset}>Try again</button>
      <a href="/">Return home</a>
    </div>
  );
}
```

### 错误过滤

**绝对不能发给 Sentry 的数据**：
- 用户对话内容
- Bazi 信息
- 邮箱地址
- 用户输入的问题

**可以发给 Sentry 的数据**：
- 错误堆栈
- 浏览器信息
- 页面 URL
- Next.js error digest
- 时间戳

Sentry 配置 `beforeSend` 过滤敏感信息：

```typescript
Sentry.init({
  dsn: process.env.SENTRY_DSN,
  beforeSend(event, hint) {
    // 移除所有包含 "message", "question", "bazi", "email" 字段的数据
    if (event.extra) {
      delete event.extra.message;
      delete event.extra.question;
      delete event.extra.bazi;
      delete event.extra.email;
    }
    return event;
  },
});
```

### 开发模式 vs 生产模式

**开发模式** (`NODE_ENV === 'development'`)：
- 显示错误堆栈（便于调试）
- 显示 Next.js 默认错误页
- **不**发 Sentry

**生产模式**：
- 只显示用户友好的错误页
- 发 Sentry（已过滤）
- 不暴露技术细节
