# POJU · 用户气泡「复制 / 编辑重发」规格（待五段调试完成后执行）

> **状态**：规格冻结，**勿在五段主链路未验收前实施完整编辑重发**。  
> **用法**：第1→第5段冒烟通过后，把本文发给 Cursor，按「执行清单」落地。  
> **日期**：2026-07-14（共识整理）

---

## 0. 执行时机（先读）

| 时机 | 做什么 |
|---|---|
| 五段主流程调试中 | **不要**做完整编辑重发；可选只做「复制」（无状态、低风险） |
| 第1→第5段验收通过后 | 按本文实施：复制 + 阶段内编辑重发 + 确认门锁 |

**更优顺序（已共识）**：先把五段跑通验稳 → 再专做编辑重发。编辑强依赖确认门边界与阶段内状态回拨，夹在大调试中间会改两遍、误伤状态机。

---

## 1. 产品目标

用户气泡下提供：

1. **复制** — 始终可用（凡允许显示动作条的用户气泡）。  
2. **编辑重发** — 仅在规定阶段、规定窗口内可用；保存后删除该条之后的聊天，并按「本段第 N 轮」回拨本段状态，然后用新文案重跑本轮。

**不做**：跨阶段回档（例如已在第3段却改第1段旧话）。

---

## 2. 五段对照（何时显示编辑）

| 阶段 | 对应状态（示意） | 复制 | 编辑重发 |
|---|---|---|---|
| **第1段 · 理解** | `opening`；未到确认门 | ✅ | ✅（仅本段用户气泡） |
| **第1段 · 确认门** | `awaiting_understanding_confirm`（总结 + 确认/补充按钮） | ✅ | ❌ 隐藏编辑 |
| **第2段 · 分析交付** | 确认后 xhigh / preparing / 分析气泡呈现 | ✅ | ❌ |
| **第3段 · 议程收集** | `collecting_context`；未到收集确认门 | ✅ | ✅（仅本段用户气泡；第1段历史只读） |
| **第3段 · 确认门** | `awaiting_confirmation`（总结 + 确认/补充） | ✅ | ❌ 隐藏编辑 |
| **第4段 · 完整交付** | 交付生成 / 已交付展示 | ✅ | ❌ |
| **第5段 · 追踪** | `tracking`（及交付后持续沟通） | ✅ | ✅（仅本段用户气泡；第1/3段历史只读） |

### 2.1 阶段归属规则（判定气泡属哪一段）

实施时需给每条用户消息打「阶段归属」（或由截断点相对确认门位置推断）：

- **第1段消息**：进入「理解确认门」之前产生的用户消息。  
- **第3段消息**：离开理解确认门之后、进入「收集确认门」之前产生的用户消息。  
- **第5段消息**：进入追踪阶段之后产生的用户消息。  

**当前阶段 ≠ 气泡所属阶段时：该气泡只显示复制，不显示编辑。**

例：人已在第3段 → 第1段历史用户气泡仅复制，不可编辑。

## 3. 编辑重发语义（核心契约）

### 3.1 跨阶段状态机：**不跳阶段、不清下一阶段产物**

编辑时：

- **不得**把 `current_phase` 改成别的大阶段（例如第3段编辑却回到 `opening`）。  
- **不得**清除下一阶段产物，例如：  
  - 在第3段内编辑 → 不得清除 `breakthrough_core` / 第2段分析  
  - 在第5段内编辑 → 不得清除第4段完整交付结果  

确认门一出现就禁编辑，从产品上保证「不会改动已进入下一阶段的输入定稿」。

### 3.2 阶段内部：**聊天 + 本段小状态一同回拨**

若本段已有多轮，用户改了其中较早一轮并 OK：

1. **聊天记录**：保留到该条用户消息（含修改后文案），**删除其后所有消息**。  
2. **本段状态**：回拨到「刚完成该轮用户发送时」的样子（像本段第 N 轮，而不是第 N+k 轮）。  
3. **然后**：用新文案在本段重新调用一轮 LLM（`userAlreadyAppended` 语义）。

例：第1段已聊 3 轮，改第 1 轮重发 → 聊天与本段状态都应变成「第1轮刚发出」的样子，再生成新回复。

### 3.3 「本段小状态」回拨范围（实施清单）

按阶段清理「编辑点之后」产生的进度，**保留**跨段定稿：

| 阶段 | 应回拨/清理（编辑点之后） | 必须保留 |
|---|---|---|
| 第1段 | `opening_substantive_turns` / 理解字段在后续轮次的增量；若截断后不再足够则不得停在确认门 | 无第2段产物（此时本就不该有） |
| 第3段 | 议程 item 的 `covered`/`partial`/`stale_turns` 等由被删轮次推进的进度；收集轮次计数 | `breakthrough_core`、第2段分析相关定稿 |
| 第5段 | 追踪向后几轮产生的临时上下文（若有） | 第4段交付、议程终态、突破核心等历史定稿 |

### 3.4 推荐收紧（降低实现难度，建议一并采用）

为减少「改第1轮却要完美重建第0轮状态快照」的复杂度，**建议 MVP 只允许编辑「当前阶段内最后一条用户消息」**：

- 仍删除其后助手消息并重发；  
- 状态回拨退化为「去掉最后一轮助手副作用」即可；  
- 与「3 轮改第1轮」的完整语义兼容，可作为第二期增强。

**规格要求**：文档与验收写明当前采用哪一档。

- **MVP（建议先做）**：仅本段最后一条用户消息可编辑。  
- **完整档（可选二期）**：本段内任意较早用户消息可编辑，并做完整本段状态回拨。

## 4. UI 行为

### 4.1 用户气泡动作条

- 图标：**复制** + **编辑**（编辑按 §2 显隐）。  
- 复制：写入剪贴板；可短暂 toast「已复制」。  
- 编辑：打开现有「编辑消息」弹窗（标题/说明可复用 i18n：`edit_message_title` / `edit_message_prompt`）。  
- 文案已存在：  
  - `poju.chat.edit_message` = 编辑  
  - `poju.chat.edit_message_title` = 编辑消息  
  - `poju.chat.edit_message_prompt` = 修改你的消息。此条之后的对话将被删除，并从修改后的内容重新开始。

### 4.2 确认门锁

以下任一为真时，**所有用户气泡隐藏编辑**（复制仍可）：

- `current_phase === "awaiting_understanding_confirm"`（第1段门）  
- `current_phase === "awaiting_confirmation"`（第3段门）  
- 第2段分析进行中（`segment2JobId` 或等价 preparing）  
- 第4段交付流水线 busy（若有）

### 4.3 忙碌 / 流式

- `sending` / 本段 LLM 进行中：禁用编辑与（可选）禁用复制点击防连点。  
- 编辑确认前：若有进行中的生成 / segment2 job，应先停止或忽略旧回调，避免幽灵写回。

## 6. 验收清单

1. **复制**：各阶段用户气泡均可复制，内容正确。  
2. **第1段**：确认门出现前可见编辑；出现确认/补充后编辑消失，仅复制。  
3. **第3段**：可编辑本段用户气泡；第1段历史仅复制；收集确认门出现后编辑消失。  
4. **第2 / 第4段**：无编辑（或始终隐藏）。  
5. **第5段**：仅本段用户气泡可编辑；第1/3段历史仅复制。  
6. **本段回拨**：在第1或第3段多轮中编辑（按 MVP：最后一条）→ 其后消息删除 → 本段进度回拨 → 重发成功 → `current_phase` 未跳错、第2段 spine（若已在第3段）仍在。  
7. **不污染下一阶段**：确认门出现后无法编辑；无法在第3段改第1段文案。  
8. **并发**：编辑时若有 generating / segment2 job，不出现旧结果写回新时间线。

## 8. 决议摘要（一句话）

**复制永远可以；编辑只在本阶段、确认门前；改哪一轮，本段聊天和本段进度就退到哪一轮；绝不靠编辑潜入下一阶段或拆掉下一阶段的定稿。**
