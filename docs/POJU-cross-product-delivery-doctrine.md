## 第一部分 · 交付层七条统一原则（所有产品照此）

这七条是底座用十几轮事故换来的。每一条后面标了**它当初是怎么被违反、造成什么后果**——这样落到新产品时，你知道在防什么。

### 原则 1 · 真数据真算 —— 给模型【真词】，不给自造术语

**做什么**：喂给模型推理的数据（神煞/十神/五行/关系/卦象/奇门符号…），一律用**模型知识体系里真实存在的原词**（天乙贵人、刑、正印、乾卦、值符…），**不要**在输入端换成我们的自造术语。

**为什么**：自造术语（提携、磨蚀）是我们发明的，模型训练数据里没有 → 它拿着不认识的词只能瞎猜 → 真算精度崩。真词才是模型能触发正确推理的数据源。

**踩过的坑**：底座 `desensitizeShensha` 在输入端把"天乙贵人"换成"提携"喂模型 → reasoning 里模型在猜"磨蚀可能指刑还是害" → 判断失准。

**红线例外**：带**恐吓/宿命/凶煞**语义的词（十恶大败、孤鸾煞、空亡、血刃、勾绞煞、童子煞…）**连真算都不喂**——它们不是中性数据源，会把宿命论算进结论，违反项目"不恐吓/不宿命"红线。这类**输入端就丢弃**。

### 原则 2 · 合规只在【输出端】，不在输入端

**做什么**：真词只活在**输入 + reasoning**（合规不查 reasoning）。到**输出（content）**，把所有裸命理词**打标 → 渲染成自造术语金字**。

**分层**：
```
输入(喂模型)   →  真词：天乙贵人、刑@year-day
reasoning      →  用真词推理（不查）
content 输出   →  ⟦t:tian_yi_gui_ren|⟧ → 渲染「提携」（金色软译 + 虚线下划线，点开看白话）
落库/下游注入  →  必须已是软译，真词不许漏出
```

**踩过的坑**：底座把"输出软译"提前到"输入软译"，既伤真算、又因别名不匹配连软译都喂不全。

**落地必查**：凡是模型输出**要落库或注入下游**的（尤其 core_judgments 这类给机器的中间层），落库前**必须过一道打标**（`autoMarkBareTerms`）。只做输入不做输出 = 真词漏进下游 = 支付合规风险。

### 原则 3 · 依据 = 完整的最短承重证据链（推理求全 / 输出求精）

**这是"依据与推理"块的核心。两端目标相反，措辞必须分开：**

**推理端（求全）**：
> 根据本段要讲清的内容，抓取相关锚点真算——抓够为止，标准是「这段讲透了、结论立得住」。
> **推理自检（下结论前）**：我这条**完整的承重证据链**搭好了吗？每个结论断言都有承重锚点撑着吗？
> 有没有关键推断还没找到支撑就想略过？**漏了承重的一环就回去补算——宁可多算一环，不可漏算关键一环。**

**输出端（求精）**：
> 依据块 = **完整的最短承重证据链**，是引证不是推理实录。
> - **最短**：推理时你可能算过很多锚点，依据里**只放本段结论真正依赖的**，无关的一个不带 → 天然不堆砌。
> - **完整**：承重的一个都不能少 —— 少一环，证据链就断，结论就悬空。
> - **不为求少而砍承重环，不为凑数而加无关环。**
> - **自检**：删掉任一金字，结论还站得住？站得住 = 那环是凑数的（删）；站不住 = 那环是承重的（留）。

**为什么分开**：用"最短"约束推理 → 诱导模型少算（偷工）；用"求全"约束输出 → 导致堆砌。**推理求全、输出求精。**

**踩过的坑**：提示词只要求"挑锚点推理"、没要求"依据只放承重的" → 依据成了推理实录，把扫过的术语全塞进去 → 密度爆表撞门禁 → 死循环。

### 原则 4 · 正文全自然语言，零标记

**做什么**：正文（用户主阅读流）**一个金字都不出现**，纯白话、通顺、有温度、有画面感。所有标记（金字）**只出现在折叠的「依据与推理」块**。

**踩过的坑**：把"白话槽会被丢弃"写进提示词 → 模型失去思考载体 → 把术语解释挪进正文 → 正文出现"正印生身，食神泄秀" → 门禁死循环。

**代码兜底**（提示词禁≠代码禁）：渲染层双层制——正文层剥标记、依据层镀金；服务端四类确定性打标器（天干/五行/十神/神煞）兜住漏网裸词。

### 原则 5 · 依据金字 = 自造术语 + 白话解释；底座固定、下游贴题

**做什么**：依据里的金字 `⟦t:slug|⟧`，渲染成**自造术语（金字）+ 可点开的白话解释**。

**白话解释分两种**：
- **底座（个人能量分析）**：**没有用户情景 → 用 SSOT 固定释义**（`definition` 字段，代码填，模型别写）。
- **下游（POJU 2/4段、Match、Glyph、Syncro）**：**有用户的具体问题/情景 → 实时生成贴合当前段落意境的白话**。同一个"提携"，在事业段和感情段的白话解释应该不同。

**踩过的坑**：底座让模型写白话槽 → 它把软译词抄进去（`⟦t:weak_self|需养⟧`）→ tooltip 变成"用这个词解释这个词"。底座该用固定模板，代码填。

**代码兜底**：白话槽 = 软译词 → 判空 → 回落 SSOT（`isNonExplanatoryPlain`）。

### 原则 6 · 绝不给正例，绝不给明确数量

**做什么**：提示词只给**定义 / 目标 / 原则 / 反例**。**绝不给正例**（✓「…」、Good:、示范句），**绝不给具体数字**（2–3 个、≥3、3–5 个、≤5）。

**为什么**：
- **正例** → 所有用户输出雷同（模型照抄示例）→ 下游拿到的全是同一份信息 → 产品死。
- **数字** → 模型锚定那个数（`≥3` 读成"正好 3"、`3–5` 让 6 环的段被砍），破坏"随内容浮动"。**数字是隐性正例。**

**踩过的坑**：底座 core_judgments 给 4 条字段正例 → 6 字段里 4 个逐字照抄；依据块给"3 环/6 环"示例 → 模型扎堆在 3 或 6。

**唯一允许的数字**：`0`（代码硬闸"0 锚点=结论悬空=判失败"）——0 不会被当成目标值去凑。

### 原则 7 · 三层防线，缺一不可

| 层 | 管什么 | 手段 | 能不能兜死 |
|---|---|---|---|
| 提示词软约束 | 方向（真算/求全/求精/贴题） | 原则 1/3/5 的措辞 | ❌ 拦不住铁了心偷懒 |
| 代码硬闸 | 底线（0 锚点、裸词泄漏、白话槽抄软译） | 打标器 / 0锚点闸 / isNonExplanatoryPlain | ✅ 兜死 |
| 人工验收 | 深度（够不够深、断没断链、贴不贴题） | 三盘对照 | ✅ 终检 |

**推论**：某盘质量差，先判断是哪层的问题。**永远不要因为质量差就退回"加正例/加数字"**——那是把软约束的锅甩给隐性正例，是这一整路的病根。

## 第四部分 · 每个产品都要过的验收（统一模板）

不管哪个产品，落完都跑这几条（**三盘对照是灵魂**）：

1. **不雷同**：三个差异大的输入 → 依据/正文两两不重复（防正例、防同质化）；
2. **真算**：reasoning 里用真词推理（不是猜软译）；结论锚到这个输入独有的算料；
3. **完整最短**：随机挑一块依据双向看——有没有凑数金字（删了结论还站）？有没有断链（结论悬空无锚点）？
4. **正文零金字**：主阅读流 0 个可点金色软译词；
5. **依据金字齐**：每个金字都渲染成"自造术语 + 白话解释"、点得开；下游产品的白话**贴当前段落意境**（不是固定模板）；
6. **无裸词泄漏**：搜真词明文（天乙贵人/刑/食神/死门…）→ 落库 content 里 0 命中；
7. **无正例残留**：全仓 grep `✓「/正例/Good:` → 该产品文件 0 命中；
8. **无数字锚定**：依据环数随内容浮动，不扎堆在某个固定数。

## 第五部分 · 建议同步进备忘录的两条新铁律

**新铁律（真词真算）**：
> 违规词是真算的**数据源**，不是脏东西。真词只在输入+reasoning，输出才软译打标。
> **合规发生在输出端，不在输入端**——在输入端阉割真词 = 让模型拿假数据算 = 真算精度崩。
> 例外：恐吓/宿命/凶煞词（十恶大败类）连真算都不喂（项目红线）。

**新铁律（推理求全/输出求精）**：
> 依据 = 完整的最短承重证据链。**推理端求全**（宁多不漏，防偷算）、**输出端求精**（只留承重，防堆砌）——两端目标相反，措辞必须分开。
> 数量由结论自己决定，提示词**不写任何具体数字**（数字=隐性正例）。唯一硬闸是 0 锚点判失败。

## 落地纪律（这几轮血泪）

1. **一个产品一份 diff，落完验收，再下一个。** 别一次全改。
2. **每份 diff 前先 `view` 该产品提示词全文**——五个产品结构不同，这份总纲给的是"思路"和"缺口"，不是可直接套用的行号。
3. **每份 diff 配一个冒烟脚本 + 一个"落地核对清单"**（防 Cursor 落一半，底座吃过这亏）。
4. **移除正例时全仓 grep**（`✓/正例/Good:/示范`），别只看手上文件。
5. **真词真算改动，务必确认"输出落库前打标"这一步**——这是唯一的合规风险点，漏了真词漏进下游。
