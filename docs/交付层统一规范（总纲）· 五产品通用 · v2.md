# POJU 交付层统一规范（总纲）· 五产品通用 · v2

> **这份是"思路"，不是"某一次 diff"。** 它把底座（个人能量分析）**二十余轮**踩坑固化成**跨产品统一原则**，
> 然后对五个交付逐个体检、给出各自的补齐清单和落地顺序。
>
> **目标、方向、话术每个产品不同——但下面这套"思路"完全一样。** 落地时一个产品一份 diff，别一次全改。

## 第零部分 · 交付流水线架构（v2 新增 · 所有产品的骨架）

底座二十余轮验证出的**核心架构**：**把"算、写、证、译"拆成独立的模型调用，各司其职。**

### 为什么拆：一次调用又算又写又打标 = 必崩

一次调用让模型同时"真算+写白话+打标+合规"，它顾此失彼——想到一个比喻就急着写、算一半去规避违规、后半段偷工。**拆开后每次只干一件事，每件都干到最好。**

### 四种调用职责（一个产品按需组合）

```
① 真算调用   —— 只推理,输出结构化【结论+命理依据】JSON,不管好不好读
② 正文调用   —— 拿结论,扩写成通顺白话正文,不碰命理词、不打标
③ 依据调用   —— 拿结论+命理真词,出"依据与推理"金字,只打标不写正文
④ 翻译调用   —— 中文成品先展开为渲染态[软译:释义],意译目标语,方括号岛回填标记
```

**每个调用都必须有匹配任务的人设**（详见下方「第零点六部分」）——人设不是可选项。

### 双钥匙（真算输出的结构 · 防正文依据脱节）

真算调用（①）每段输出**两把钥匙**，锁死②③围绕同一结论、各取所需：
```
core_conclusion —— 白话结论（②写正文用它,③锚结论也用它 → 绝不两张皮）
bazi_basis      —— 命理依据清单（术语保留 + 白话连接；③照单打标,不猜、不从正文反推）
```
**③ 绝不能看②的白话正文**——②已把命理词洗成白话，③对着白话反推依据 = 打标幻觉。③必须直接读①的真词清单。

**真算内部「先算后译」**：推理阶段可用命理行话（最准）；**写进 `bazi_basis` 时整条换成白话成品**（术语保留、行话动词翻成人话、五行连写拆开加"和"）。行话草稿不输出 → 下游拿到的天然是白话版，schema/`string[]` 与取值代码零改动。

### 时序（串行根 + 并行枝）

```
① 真算(串行先行,是根,必须成功才往下)
  → ②正文 ③依据 并行(都只依赖①,互不依赖)
  → ④翻译(外文站才有,②③完成后)
总时长 ≈ ① + max(②,③) + ④
```

### 分 Task 并发（段落多时防塌陷）

**段落多的交付**（底座19段），②③④**各拆成按模块的并发 Task**（每Task 4-6段）。原因：**一次让模型输出十几段，后半段必偷工/漏段/截断**（血泪验证两次）。拆Task后每次任务轻，不塌陷。段落少的交付（第2阶段）**不拆**。

## 第零点五部分 · 中文底层 + 翻译层（v2 新增 · 多语言统一方案）

**铁律：真算、正文、依据全程用中文；多语言只在最后一次【翻译调用】处理。**

### 为什么全中文推理

命理概念是**中文原生**的——"丁火食神泄身""日主弱需水木扶助"翻成英文后，模型理解的**已不是那个精确的中国命理概念**，推理必然失真（=瞎算）。所以：
- **真算/正文/依据 全程中文**（推理零失真）
- **"中文推理→外文输出"不可取**——模型在语言切换边界会漏切 → 中英混杂（血泪验证）

### 翻译层怎么做（④ 翻译调用）

```
中文站: ①②③ → 直接交付           (不翻译)
外文站: ①②③(全中文) → ④翻译 → 交付
```

**④ 翻译调用三要素：**
1. **母语者人设**（按 locale 动态）——"你是一位[美国]人，母语[英语]，同时精通中国易经五行命理"。**母语者人设 > 多语言工作者人设**（后者出翻译腔）。
2. **喂页面渲染态依据**——代码把 `⟦t:slug|⟧` 展开成 `[软译:释义]`（中文 SSOT 平替后的读者可见形态）再送给模型；**不**再注入代号大表、**不**喂真算底稿。模型先理解整段意思再意译；禁止字面直译（可用反例钉失败模式）。
3. **方括号岛原样保留 → 代码回填标记**——`[软译:释义]` 不翻译；译后按序还原为 `⟦t:slug|⟧`（前端再按目标语 SSOT 渲染）。漂移时用原文标记回填，不打回。

**分 Task**：段落多时翻译也拆4Task并发（按模块，正文+依据一起翻，Task内配对呼应）。

**扩展性**：加新语言 = SSOT 补该语言列 + 母语者人设加一行 + 语言列表加一项。翻译逻辑不动。

## 第零点六部分 · 人设是每个模型调用的标配（v2 新增 · 质量地基）

**铁律：每个模型调用，都必须在 system prompt 开头给一个【匹配该调用任务的人设】。**

人设让模型进入对的角色状态，是质量的地基。**人设要精准匹配任务，不是笼统套"命理师"：**

| 调用类型 | 任务重心 | 人设匹配 |
|---|---|---|
| **纯推理**（①真算） | 算得准、结构化 | "精通命理的分析师"（强调推理、算得准） |
| **白话写作**（②正文） | 读懂术语 → 翻成温度白话 | "深度洞察 + 白话写作功底的写作者"；**必须能准确读懂算料里的专业命理术语**（输入含术语，看不懂就会翻跑偏） |
| **论证+解释**（③依据） | 挑承重真词作证 + 白话连接 | "精通命理 + 能讲人话的专家"（两者融合，不照抄真算的纯分析师） |
| **翻译**（④） | 地道母语 + 懂原文 | "目标语言母语者 + 精通易经五行命理"；入参为渲染态 `[软译:释义]`，意译禁直译 |

**反例**：只给任务不给人设（"你在给报告写小结"）→ 模型没进入角色 → 质量最不稳。底座依据调用曾因此成为四调用里质量最差的一环——补上"精通命理 + 讲人话"双能力人设后才稳住。

**落地自检**：改任何交付的 prompt 前，先问——这次调用的 system 开头有没有匹配任务的人设？缺则补，笼统则改准。

## 第零点七部分 · 不打回，只清洗（v2 新增 · 最重要的稳定性原则）

**铁律：任何模型调用，除"JSON 彻底解析失败"外，一律不打回重算；内容不合规靠代码清洗，不靠重新生成。**

### 为什么（黄金首生成）

**第一次生成质量最高**——模型首次注意力全在深度推导，能抓到"丁壬合""乙木如藤萝"这种灵性细节。**一旦因合规打回重算，模型注意力转向"规避违规"，过度矫正，把惹祸的深度细节全删掉 → 越重试越差**（血泪验证：重试3次一次比一次干）。

### 怎么做

```
真失败(空/截断/JSON解析失败/结构坏) → 同参数无感重发(这些是"没有输出")
内容不合规(简称/时间锚/裸词/角引号)  → 【代码清洗放行】,绝不打回:
  简称   → sanitizer 按本命上下文还原全称;还原不了→【】中性平替
  裸词   → autoMarkBareTerms 补打标
  时间锚 → 就地删/转中性词(输出端拦)
  角引号 → 代码剥除
```

**中间数据 vs 输出数据，审的标准不同**：
- **中间数据**（真算给机器的算料）：只审"结构可用"（JSON对），简称/时间锚这类**能修就修、修不了留输出端**，绝不打回。
- **输出数据**（用户可见的正文/依据）：合规靠**代码清洗**（软译/剥违规），仍**不打回**。

### 连带的坑（血泪）

- **别套"拦截式 gate"**——底座曾在末尾套 v1 的"违规就 failJob→前端重试→整轮重跑" → 19次调用、超时。gate 只能**观测记日志，绝不 failJob**。
- **异步 job 的锁 TTL 必须 > 单轮耗时**——锁 300s < 单轮 335s → 锁中途过期 → 第二请求穿透 → 整轮重跑。锁要覆盖单轮。

## 第一部分 · 交付层七条统一原则（所有产品照此）

这七条是底座用二十余轮事故换来的。每条标了**它当初怎么被违反、造成什么后果**。

### 原则 1 · 真数据真算 —— 给模型【真词】，不给自造术语

**做什么**：喂给模型推理的数据（神煞/十神/五行/关系/卦象/奇门符号…），一律用**模型知识体系里真实存在的原词**（天乙贵人、刑、正印、乾卦、值符…），**不要**在输入端换成我们的自造术语。

**为什么**：自造术语（提携、磨蚀）模型训练数据里没有 → 拿着不认识的词瞎猜 → 真算精度崩。真词才是模型能触发正确推理的数据源。

**踩过的坑**：底座 `desensitizeShensha` 在输入端把"天乙贵人"换成"提携"喂模型 → reasoning 里模型在猜"磨蚀可能指刑还是害" → 判断失准。

**红线例外**：带**恐吓/宿命/凶煞**语义的词（十恶大败、孤鸾煞、空亡、血刃、勾绞煞、童子煞…）**连真算都不喂**——它们不是中性数据源，会把宿命论算进结论。这类**输入端就丢弃**。

**v2 补充**：五行金木水火土**本身不违规不难懂**，不该软译打标（火→发散是负收益：降可读性、增打标出错、标记密度爆表致渲染崩）。**五行原字直接用，不打标**；只有十神/神煞/天干/用神喜忌这类专业词才打标。

### 原则 2 · 合规只在【输出端】，不在输入端

**做什么**：真词只活在**输入 + reasoning**（合规不查 reasoning）。到**输出（content）**，把裸命理词**打标 → 渲染成自造术语金字**。

```
输入(喂模型)   →  真词：天乙贵人、刑@year-day
reasoning      →  用真词推理（不查）
content 输出   →  ⟦t:tian_yi_gui_ren|⟧ → 渲染「提携[···]」
落库/下游注入  →  必须已是软译，真词不许漏出
```

**踩过的坑**：底座把"输出软译"提前到"输入软译"，既伤真算、又因别名不匹配连软译都喂不全。

**落地必查**：凡模型输出**要落库或注入下游**的，落库前**必须过一道打标**（`autoMarkBareTerms`）。

### 原则 3 · 依据 = 完整的最短承重证据链（推理求全 / 输出求精）

**推理端（求全）**：
> 根据本段要讲清的内容，抓取相关锚点真算——抓够为止，标准是「这段讲透了、结论立得住」。
> **推理自检**：完整的承重证据链搭好了吗？漏了承重的一环就回去补算——**宁可多算一环，不可漏算关键一环。**

**输出端（求精）**：
> 依据块 = **完整的最短承重证据链**，是引证不是推理实录。
> **最短**：只放本段结论真正依赖的锚点，无关的一个不带。**完整**：承重的一个都不能少。
> **自检**：删掉任一金字，结论还站得住？站得住=凑数（删）；站不住=承重（留）。

**为什么分开**：用"最短"约束推理→诱导偷工；用"求全"约束输出→导致堆砌。**推理求全、输出求精。**

**v2 补充（阶段性质决定要不要依据）**：**不是所有交付都出依据。** 交付先问自己：**这是"问诊"还是"结论"？**
- **结论型交付**（底座、POJU第4段、Match、Glyph、Syncro）→ **出依据**（严谨论证"我为什么这么判断"）。
- **问诊型交付**（POJU第2段）→ **不出依据**。第2段是"术前沟通"——医生说"我打算往这几个方向帮你，你看行吗、还有什么补充"，本质是**问诊、确认、开放收集**，不是下结论。**过早出依据 = 越位下结论 = 破坏"你还有什么补充"的开放性。** 依据是第4段"正式手术"才有的东西。

### 原则 4 · 正文全自然语言，零标记

**做什么**：正文（用户主阅读流）**一个金字都不出现**，纯白话、通顺、有温度、有画面感。所有标记只在折叠的「依据与推理」块。

**踩过的坑**：把"白话槽会被丢弃"写进提示词 → 模型把术语解释挪进正文 → 门禁死循环。

**代码兜底**：渲染层双层制——正文层剥标记、依据层镀金；服务端确定性打标器兜住漏网裸词。

**v2 补充**：正文分段**不能依赖模型写不写换行**（模型写了有排版、没写就渲染错乱）。正文规范成独立块（后端处理），正文↔依据渲染层**强制1对1**（正文块缺失则对应依据也不显示，绝不出现孤立依据）。

### 原则 5 · 依据金字 = 自造术语 + 白话解释；底座固定、下游贴题

**做什么**：依据里的金字 `⟦t:slug|⟧`，渲染成**自造术语（金字）+ 可点开的白话解释**。

**白话解释分两种**：
- **底座（个人能量分析）**：无用户情景 → 用 SSOT 固定释义（`definition` 字段，代码填，模型别写）。
- **下游（POJU 4段、Match、Glyph、Syncro）**：有用户具体情景 → 实时生成贴合当前段落的白话。

**踩过的坑**：底座让模型写白话槽 → 抄软译词进去 → tooltip 变成"用这个词解释这个词"。

**代码兜底**：白话槽=软译词 → 判空 → 回落 SSOT。

### 原则 6 · 绝不给正例，绝不给明确数量

**做什么**：提示词只给**定义 / 目标 / 原则 / 反例**。**绝不给正例**（✓「…」、Good:、示范句），**绝不给具体数字**（2–3个、≥3、3–5个）。

**为什么**：正例→所有用户输出雷同（照抄示例内容）→产品死。数字→模型锚定那个数→破坏"随内容浮动"。**数字是隐性正例。**

**踩过的坑**：底座 core_judgments 给4条字段正例 → 6字段里4个逐字照抄。

**唯一允许的数字**：`0`（代码硬闸"0锚点=结论悬空=判失败"）。

**v2 补充**：这条在多次调用架构下**每一次调用的 prompt 都要守**。尤其真算调用的骨架 JSON——给字段留空示意可以，**绝不能在示意里填正例内容**（会被逐字照抄）。

**例外（格式转换 · 非内容创作）**：真算 `bazi_basis`「行话→白话」这类**动作/程度示范**，可给**一个**正例锚定"翻到多白"——学的是转换程度，不是抄内容；每个盘术语不同，不会千篇一律。**内容创作（正文/依据/core_conclusion）仍绝对禁止正例。**

**（教训）零散列举当完整规则**：列几个行话动词 → 模型只翻列的、漏没列的（生扶/帮身/半合漏翻就是这么来的）。正解三管齐下：① 禁词**按类给**（整类都要翻）；② 「不止这些」+「初中生听得懂吗」检验标准兜底；③ 格式转换可加一个程度正例。

### 原则 7 · 三层防线，缺一不可

| 层 | 管什么 | 手段 | 能不能兜死 |
|---|---|---|---|
| 提示词软约束 | 方向 | 原则 1/3/5 措辞 | ❌ 拦不住铁心偷懒 |
| 代码硬闸 | 底线 | 打标器/0锚点闸/清洗/平替 | ✅ 兜死 |
| 人工验收 | 深度 | 三盘对照 | ✅ 终检 |

**推论**：质量差先判断是哪层问题。**永远不要因为质量差就退回"加正例/加数字"**——那是病根。

**v2 补充**：合规现在是**三层纵深**——门面/正文层（零命理词）+ 结论层（真算 phase_states 零时间锚）+ 依据层（可用真词但禁时间锚/疾病）。且全靠**代码清洗**实现，不靠打回（第零点七部分）。

## 第二部分 · 五产品交付流程（v2 架构下的调用组合）

每个产品按"算/写/证/译"四种调用**按需组合**。核心差异在**要不要依据**（问诊 vs 结论）和**段落多少**（拆不拆Task）。

| 产品 | 性质 | 调用组合 | 说明 |
|---|---|---|---|
| **底座**（个人能量分析） | 结论 | 1真算 + 4正文 + 4依据 + 4翻译 | 19段多,②③④各拆4Task并发防塌陷 |
| **POJU 第2段**（破局方向） | **问诊** | **1真算 + 1正文 + 1翻译** | **不出依据**(术前沟通,非结论);段落少不拆Task |

> **POJU 第2段为什么不出依据**（重要）：它是**问诊阶段**——像医生术前说"我打算往这几个方向帮你，你看行吗、还有什么补充"。目的是**更好了解用户**，不是下结论。出的"议程"也是为了收集更多信息。等医生对病情了解透了，才动第4段的"手术"（完整带依据交付）。**第2段出依据 = 越位下结论 = 破坏开放性。**

## 第五部分 · 每个产品都要过的验收（统一模板）

## 第六部分 · 备忘录新铁律（v2 批量新增）

**真词真算**：违规词是真算的数据源不是脏东西。真词只在输入+reasoning，输出才软译打标。恐吓/宿命词连真算都不喂。

**推理求全/输出求精**：依据=完整的最短承重证据链。推理端求全、输出端求精，措辞分开。数量由结论决定，不写具体数字。

**（新）真算先算后译**：推理用行话（最准），写进 `bazi_basis` 时翻成「术语保留+白话连接」（可读）。行话是推理燃料，白话是输出成品；让最懂行话的真算自己翻，比让下游猜着翻更准。下游只取白话成品，行话草稿不外传——是「推理求全/输出求精」在真算侧的延伸。**行话白话化：按类给禁词 +「初中生听得懂吗」标准兜底 + 格式转换可给一个程度正例**；禁止零散列举几个动词当完整清单（模型会只翻列的、漏没列的）。

**（新）每个产出白话的调用各自装完整白话化机器**：不能假设「上游白话了、我沿用即可」。下游（尤其依据）是「重新组织语言」不是「照抄」——重组过程会滑回行话（帮身/当令/辰中藏/贴身/透出…）。真算白话了，依据仍需自己的分类黑话表 + 初中生检验标准 + 程度正例（依据正例带 `⟦t:slug|⟧` 打标）。白话化要求要在每个输出白话的环节各装一套，不能只装一处指望传导。附：prompt 前缀缓存只省速度/成本、不降质；命中缓存是静态前缀在上层生效的好现象。

**（新）多次调用分离**：算/写/证/译拆成独立调用，各司其职。双钥匙锁正文依据同源。段落多则拆Task并发防塌陷。

**（新）人设是每个调用的标配**：system 开头必须有【匹配该调用任务的人设】——纯推理≠白话写作≠论证解释≠翻译。人设让模型进入对的角色，是质量地基。缺人设的调用质量最不稳（底座依据是活例子）。

**（新）中文底层+翻译层**：命理推理全程中文（翻译即失真）。多语言只在末次翻译调用：母语者人设 + 渲染态`[软译:释义]`入参 + 意译禁直译 + 方括号岛回填标记。加语言=补数据不改逻辑。

**（新）不打回只清洗**：除JSON彻底解析失败外一律不打回。首次生成质量最高，重试过度矫正退化。合规靠代码清洗（还原/平替/补标/剥除），不靠重新生成。gate只观测不failJob。锁TTL>单轮。

**（新）阶段性质决定依据**：交付先问"问诊还是结论"。问诊型（第2段术前沟通）不出依据，保持开放；结论型（手术级交付）才出依据。

**（新）正文分段不依赖模型**：正文规范成独立块（后端），正文↔依据渲染强制1对1，正文缺则依据也不显示（不出孤立依据）。五行原字不打标（降标记密度+提可读性）。
