## 一、铁律（违反过的，都写在这）

### ⚠️ 1. 提示词只给【定义 / 目标 / 原则 / 反例】，**绝对禁止给【正例】**

**这是项目第一禁忌。用户已多次强调。写正例 = 所有用户的输出长一个样 = 下游拿到的全是同一份信息 = 产品死。**

**实证事故 ×5（全是我犯的，前 3 条是旧账，后 2 条是 2026-07 全测试挖出来的现行犯）：**

| # | 事故 | 后果 |
|---|---|---|
| 1 | 底座 few-shot 写了「手机散热片」 | **每个用户的底座都这么说** → 经注入**传染进 POJU** |
| 2 | 我建议收尾「这不是命定」 | 模型写出「不是你的**命运**判决书」→ 撞禁词、整篇作废 |
| 3 | 提示词禁「引擎」还举了例 | 模型推理里**明说知道禁用**，仍写「你不是一台…**引擎**」 |
| 4 | `generate-core-judgments.ts:109-112` 给了 4 条字段正例 | 模型 **6 个字段里 4 个逐字照抄**；没给正例的 `exchange_mode`/`leverage_state` 才是它自己写的 |
| 5 | `banned-terms.ts:286` ✓「你的力量来自吸收与转化…」／`base-analysis-stream-prompt.ts:152` ✓`⟦t:day_master\|如盆景般需精准滋养的柔韧生长力⟧` | 底座报告写出「你的价值不在硬扛，而在吸收、消化…」「如**河畔垂柳**般的柔韧核心」——**换个植物就交差** |

**精确边界（已验证）：正例会被逐字照抄；反例不会。**

**根因（事故 #4 教会我的，别再忘）：**
> **当提示词只给字段名 + 正例、不给字段定义时，正例就成了字段唯一的语义来源 —— 模型除了照抄别无选择。**
> 它的 reasoning 会明写「调节阀**可能指**水还是金？」——它在猜。
> **正解不是"警告它别抄"，是把定义写出来，然后把正例删掉。**

**落地要求（每次写/改提示词都过一遍）：**
1. 每个字段必须有**定义**（这个字段是什么、读什么、不读什么、边界在哪）；
2. 反例照给（反例不定义字段，不会被抄）；
3. 正例**一条都不给**——包括「正例方向」「Good:」「✓「…」」「示范句」这些马甲；
4. **代码门禁**：输出 ≈ 提示词里任何常量串 → 判失败 → 同参数无感重发（光靠提示词自觉不行，见铁律 2）；
5. 改任何提示词前，先 `grep -rn "正例\|✓ \|Good:\|示范" lib/` 全仓扫一遍，别只看手上这个文件。

### 2. 提示词禁 ≠ 代码禁
关键边界（分段隔离、放行、显示什么、禁词、**正文零标记**）**必须代码硬兜死**，模型会绕道。
**推论**：输入端喂了裸词，就别指望提示词让它别用（Glyph 现在正是如此）。

### 3. 控制面决策、数据面执行
进不进下一段由**用户明确点击**（确认门）决定，不靠模型猜意图。
**但**："这一项答透没有"是**语义**判断，不能降格成"用户有没有说话"（第3段现在正是这个病）。

### 4. 凡是代码能确定的，绝不让模型做
- 排版结构 → 代码按行号打补丁，别让模型重吐全文（它必重排版、洗掉换行）；
- `climate_now` / `refs` → 代码从 structured 填，别让模型猜（它会陷入"大运干支未提供"的无解长考 → 空回复）；
- 长度约束 → 用**句数**不用**字符数**（字符数会诱发计数强迫症 → 烧光 token → 截断）；
- **标记白话槽**：底座只有八字、**没有用户情景 → "贴题白话"是伪需求**，代码从 `pojulife-terms.ts.definition` 填（固定模板，5 语言已齐）。**只有第2/4段与其他产品有用户情景，才让模型实时写贴题白话。**

### 5. 静默兜底 = 失败永远看不见
matrix-narrative 500 被模板静默盖住、补丁失败被静默整篇重生成、**core_judgments 4 条抄正例被黑话闸放行** —— **任何 fallback 必须响亮告警 + 面板标注。**

### 6. 对照能成功的基线
遇"同模型 A 路径行 B 路径不行"→ **第一步系统性对比 A/B 代码差异**（base_analysis 流式 job 就是那个对照组），别逐个猜参数。

### 7. xhigh 是高消耗模式
慢(~168s)、吃 token(22000+)、易崩 JSON。**配置按真实胃口给足，别想当然"优化"减配**（我因此连错三版：90s超时 / 12000token / max_attempts:1）。

### 8. 概率性失败的正解 = 同参数无感重发
不追求单次 100% 正确（做不到）；**坏了就丢、同参数重发到成功**（不降质、不换候选、不弹报错）。
**空回复 ≠ slug 失效。**

### 9. 用架构消除整类 bug
确认门(消除猜意图) / 异步job(消除90s墙) / 同参重发(消除偶发露底) / 代码物理隔离(消除改A坏B) / 双层制(消除专业与可读打架) / **渲染层分层(消除"代码把白话改成金字")**。

### 10. 单一事实源
禁词表/黑名单/术语表 **只能有一份**，门禁+替换器+提示词**全部从它读**并**自动注入** —— 分开维护必然漂移。
**已破的账**：`身弱` 现有 4 份脸（`pojulife-terms`「需养」／`banned-terms:49-58`「能量供给容易跟不上」／`term-glossary-closed:343`「燃料容易跟不上」／`base-analysis-stream-prompt:133` 提示词硬写）；`流年` 有 2 份（「岁环」／「当前时空效能」）。

## 二、已验证的系统事实

### 底座（命主基础分析）
- **两层**：Layer1 给机器（`structured` + `core_judgments`）／Layer2 给人（叙事，**绝不注入下游**）；
- **目标 2 次调用**：core_judgments 1 + 叙事 1（欢迎词已改**纯模板、0 调用**）；
- **门禁只拦叙事**；`core_judgments` 无用户可见文本 → 第一次即落库；
- 神煞闭集 **24** 个（`CLOSED_SHEN_SHA` / Block 62）；本盘只用实例清单实算项；`国印/将星/月德/天德/学堂` 等已在闭集内（算出才可写）。
- **`core_judgments` 现状（2026-07 实测）**：6 字段里 4 条逐字抄提示词正例；抄出来的内容 ≈ 代码兜底 `buildCoreJudgmentsFromStructured` 的输出（那次 medium 调用等于白烧）；`refs` 里的 17 个神煞 + 本命关系**一条都没被消化**；`balance_anchor`/`leverage_state` 越界写成了行动建议（第4段的活）；`hasCoreJudgmentsBlackspeak` 只查裸词、**不查照抄**。
- **`climate_now` 只有 6 种句子**（`core-judgments.ts:216-252` 只看大运天干五行 vs 用神，不看地支、不看流年）——粗，但确定性，符合铁律 4。

### 标记 / 白话槽（`⟦t:slug|贴题白话⟧`）
- `rewriteMarkersWithSsotSoft:692` = `plain || glossOf(id) || soft` → **模型写了就赢，SSOT 定义永远轮不上**；
- 模型的懒法不是留空，是**把软译词抄进白话槽**（`⟦t:weak_self|需养⟧`）→ tooltip 变成"用这个词解释这个词"；实测 **13 个标记里 12 个如此**；甚至 `⟦t:yong_shen|润流⟧`（抄错成 water 的软译）→ 点开「锚元」弹出「润流」；
- **留空是好事**（`⟦t:slug|⟧` → glossOf 顶上）；`⟦t:slug⟧` 不行——`TERM_MARKER_PATTERN:146` 要求至少一个 `|`，否则整标记被当破损剥掉；
- 懒的来源：`buildTermMarkingPromptBlock:870-872` 注入的表**带软译列**，模型没主意就从表里抄。

### 四产品交付结构（已定案）
```
正文（纯白话 · 零标记 · 有温度）
  ▸ 结构依据（默认折叠 · 金字集中 · 允许"不好读"）
```
- **结构依据 = 支撑该段结论的【最短承重证据链】**（2 句 / ≤3 金字），**是引证不是推理实录**；
- **依据先行**：先锁 2–3 锚点 → 据此推结论 → 写正文 → 落依据。**自检：删掉依据，结论还站得住？站得住＝泛泛而谈＝重写。**
- **它是逼模型真算的枷锁**，不只是给用户看的证据。
- **渲染层病根（已定位）**：`GlossaryText.tsx:333` 的 `MarkedInline` 不区分正文/依据，对所有文本跑 `autoMarkBareTerms` → 「平衡」（`CLOSED_STRUCTURAL:108` 里唯一的日常词）被改写成金字「均势[···]」，连动词都换成名词（"来均势耗元"）。**不是模型违规，是代码把白话改成了金字。**

同参数无感重发只对【概率性失败】有效。
对【确定性失败】(finish_reason=length / 预算不够 / 提示词自相矛盾),重发只是把一次失败乘以 N。
分辨方法:连续 N 次结果完全一样(同样的 output token 数、同样的 finish_reason)= 确定性失败 → 去改配置,不是加重试。
